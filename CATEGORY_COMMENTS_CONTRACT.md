# Комментарии к общим категориям молитвенника

Проверенные базы `origin/main` — Web `c2cca9e2ec80c91d1645556d71062c9090435303` и Flutter `3b4a29dae7b5ecb8cd7cd268dba1d13b207be160`. Формат `comment` из первой ревизии сохраняется поверх Access Sets V2 и дополняет [контракт дерева категорий](docs/prayer-categories-contract.md), [контракт Access Sets](docs/access-sets-contract.md) и [интеграцию S8](docs/access-sets-s8-integration.md).

## Документ категории

Добавляется одно необязательное поле `comment` в полных документах общих категорий. Публичный документ хранится в `prayerCategories/{id}`, защищённый канонический в `protectedCategories/{id}`. Совместимое зеркало `priestProtectedCategories/{id}` существует только для документов с `effectiveAccessSets: ['priest']`. Личные категории, молитвы и их черновики используют свои существующие модели.

Существующий документ:

```json
{
  "id": "sample-leaf", "name": "Прыклад", "parentId": "sample-root",
  "order": 10, "tags": [], "prayerIds": [], "priestOnly": false
}
```

Тот же документ с комментарием:

```json
{
  "id": "sample-leaf", "name": "Прыклад", "parentId": "sample-root",
  "order": 10, "tags": [], "prayerIds": [], "priestOnly": false,
  "comment": {
    "title": "Тлумачэнне",
    "content": "Узор **афармлення**.\n\n> Прыклад цытаты.\n\n:::rubric\nПрыклад рубрыкі.\n:::",
    "sourceId": "ojcha-nash-2022"
  }
}
```

- `id` берётся из имени Firestore-документа и присутствует в экспортных данных. Дочерние категории отличаются обычным `parentId`.
- `content` — строка в существующем формате `mybrev-markdown` версии 1. Поддерживаются абзацы, заголовки, списки, цитаты, выделения, ссылки и блоки `:::rubric`. Разметка использует структурный рендерер с отключённым HTML. При сохранении переводы строк приводятся к LF, остальная разметка и текст сохраняются. Отсутствующий или `null`-комментарий, а также отсутствующий, `null`, нестроковый или пробельный `content` означают отсутствие блока. При очистке редактор удаляет карту из документа. Титул и источник сами по себе блок не создают.
- `title` — необязательная строка простого текста. Пробельный заголовок равнозначен отсутствующему. Заголовок по умолчанию — «Пра гэты раздзел». Каждый новый вход на страницу начинает со свёрнутого блока. Комментарий открывается до подкатегорий и записей. Категория с одним комментарием и её доступные предки участвуют в прежнем дереве. Поиск и избранное продолжают работать по молитвам.
- `sourceId` — необязательный ID из общего библиографического справочника. Web использует `src/data/sourceBibliography.json`, Flutter — `lib/constants/source_bibliography.dart`. Оба содержат `ojcha-nash-2022`, «Малітоўнік «Ойча наш» (Мінск, 2022)». Использовать его после сверки издания с оригиналом. При неизвестном ID читатель показывает комментарий без строки источника. Библиографическая строка отображается при раскрытии.
- Комментарий получает доступ категории и предков по действующей V2-политике. `priest` и `marian` независимы. Canonical writer принимает только собственные `accessSets`, вычисляет `effectiveAccessSets`, атомарно записывает полный payload, пустые записи per-set индексов, `contentHash`, подходящее priest-зеркало, версию и аудит. В `legacy` остаётся прежний `mutatePrayerContent` с `effectivePriestOnly`. В `suspended` действуют штатные ограничения записи и чтения S8. `prayerCategoryService.js` сохраняет комментарий только при наличии поля в patch. `null` используется для явной очистки, после которой оба writer удаляют только `comment`. Для canonical очистки перед выпуском нужен обновлённый `canonicalCatalog` с `applyEdit` из этого PR. Правила, политика наследования и индексы сохраняются.
- У категорий нет процесса черновиков. `prayerDrafts` — отдельная закрытая коллекция. Прямые ссылки `prayerIds` указывают на опубликованные записи. Из публичного экспорта исключаются категории и ветки с явным `published: false` или статусом `draft`, `pending`, `review`, `rejected` либо `archived` по существующему `publicPrayerRows`.

## Web, Flutter и выпуск

| Путь | Чтение и совместимость |
| --- | --- |
| Web Hosting | `export-public-prayers-hosting.mjs` использует `publicPrayerRows` и `buildPublicPrayerCatalog`, включая существующие исключения по canonical и mirror путям. Публичные комментарии идут в том же `/public-prayers-v1.json` как необязательная верхнеуровневая карта `categoryComments` вида `{ "sample-leaf": { "content": "…" } }`. Новый валидатор проверяет ID и вложенные поля. Старый Web валидирует поля внутри `categories[]` и `prayers[]`, а дополнительные ключи корня игнорирует. Старый файл без карты и прежние офлайн-кэши читаются новым Web. |
| Web reader и админка | `usePrayerCatalog` и `accessSetsCatalogSession` получают разрешённые документы по прежним путям, а `prayerCategories` очищает защищённые строки при смене поколения. Экран читает комментарий только из актуального store и сбрасывает раскрытие для защищённой категории при смене поколения. Editorial catalog отделён от reader и его кеша. Комментарий-only лист влияет на видимость после этой авторизации. |
| Flutter bundle и обновления | `scripts/content/lib/app-content.mjs`, `build-app-bundle.mjs` и `publish-manifest.mjs` используют существующий `publicPrayerRows` и исключают закрытые и неопубликованные категории. У допущенного документа публичный `comment` входит в общий хеш и сохраняется без переписывания, чтобы совпасть с исходным документом при обновлении. Bundle и манифест остаются версии 1. `lib/content/content_bundle.dart` распаковывает карты, `content_store.dart` загружает их в Hive, `content_updater.dart` обновляет по манифесту. `lib/providers/prayer_categories_provider.dart` передаёт в `PrayerMenuCategory.global` карты из авторизованного снимка или публичного Hive. B добавляет в этой модели optional comment и видимость comment-only листа после авторизации. |
| Выпущенные клиенты | В старом Flutter `PrayerMenuCategory.global` читает известные ключи, а `buildPrayerCategoryMenu` отсеивает лист без разрешённых молитв. Неизвестная карта совместима при чтении, но на старом Flutter «Пасвячэнне» будет скрыто. Старый Web игнорирует карту Hosting и также скрывает лист в меню. Наличие молитв в других ветках сохраняет старое поведение этих веток. |

1. Выпустить поддержку чтения на Web и Flutter. B проверяет Markdown, источники, Hive и поведение пустого листа на Android и iOS. Проверить fallback со старым bundle. До этого работать на fixtures. Для старых клиентов, которые продолжат использоваться после выпуска, владельцу нужно принять отсутствие «Пасвячэнне» или выбрать доступную ему политику обновления. Временная фиктивная молитва не нужна.
2. Пакет C содержит 8 комментариев, 8 категорий и 24 размещения. D принимает подготовленный пакет и проверяет, что все повторно используемые ID уже опубликованы и доступны гостю. Подкатегории идут по `order` внутри `parentId`. Для явного состава новых категорий предусмотрены `tags: []` и `prayerIds` из публичного каталога. «Пасвячэнне» получает пустой `prayerIds` и комментарий.
3. #328 сохраняет порядок полного явного `prayerIds` только для защищённого корня Web. Публичные дочерние категории используют избранное и заголовок. Для D и Flutter предлагается отдельное согласование `prayerOrder: "manual"` на документе категории. Только явно помеченная категория применяет порядок разрешённых ID в `prayerIds` после фильтрации. Остальные разрешённые прямые записи идут следом в текущем порядке. Режим потребует согласованного экспорта нового признака и проверки на обеих платформах. До отдельного одобрения и проверки экранного порядка 24 размещений пакет остаётся за воротами импорта. Сериализация комментария от этого решения не зависит.
4. Выпуск `canonicalCatalog` согласуется отдельно по [действующей процедуре](docs/access-sets-s4-callable.md). После отдельных одобрений импорта и статусов Hosting публикуется вручную с утверждённым SHA. Для Flutter выполнить `npm run content:manifest` и опубликовать только проверенный `SAFE CONTENT PATCH` с явным `-- --apply`. Массовое обновление или смена схемы идут через `npm run content:app-release` с выпуском приложения. ## Проверки и расход Firebase

- Локальные данные — `backups/firestore-snapshot` в основном checkout от 27.08.2026 не содержит коллекций молитвенника. Резервный `firestore-snapshot-prayers` от 28.08.2026 содержит 85 молитв и не содержит категорий. Версионированный `assets/content/prayerCategories.json.gz` в Flutter `main` содержит 22 категории без `comment`. Полнота боевых данных, совпадения записей и издание раздела требуют отдельной редакционной проверки.
- Web — старые категории, отсутствующее/`null`/пустое поле, короткий и длинный Markdown, рубрика и источник, дочерний лист с нулём молитв, возврат на страницу, клавиатура и `aria-expanded`, размеры экрана, темы и читательские настройки. Админка — создание, повторное открытие, правка, очистка, целостность существующих полей и наследование доступа. Публичный экспорт — проверка старого валидатора, допустимых вложенных полей и исключения защищённых и неопубликованных комментариев.
- Flutter — старый bundle с новой моделью, новая карта в старой модели, форматированный текст с источником, видимость пустого листа по прежней навигации, офлайн и обновление версии через Hive, защита закрытых категорий. Тест выпуска — порядок, 24 размещения и отсутствие утечки в bundle, поиск или избранное.
- Аудит и локальные проверки требуют 0 production-чтений и 0 production-записей. Web читает публичный каталог тем же запросом к Hosting. Раскрытие комментария и группировка Drawer используют уже загруженный авторизованный payload. Публикация продолжает читать шесть существующих коллекций и проверяет прежний bracket версии. Flutter использует bundle/Hive и текущий цикл синхронизации. При обновлении новый или изменившийся комментарий входит в одно штатное чтение изменённого документа категории.
