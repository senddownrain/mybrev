# Малітоўнік — выбранный брендовый знак

Внедрён первый вариант, выбранный владельцем: тёплый круг, живой белый голубь
Святого Духа, раскрытая молитвенная книга, крест и мягкие лучи. Это выбранный
рисунок из второй серии, а не геометрический A1 из отклонённых эскизов.

## Мастер и экспорты

`source/approved-icon.png` — неизменённый выбранный исходник 1254×1254,
SHA256 `fa8ac6990b67f4a48e5907d00c86aa7306fb44921f079dd5bc92c7bba682a294`.
`source/design-selection.md` сохраняет промпт и историю выбора.
`source/monochrome.svg` — редактируемая оптическая микроверсия голубя и книги
с ясно вырезанным крестом. Исходник подробной иллюстрации остаётся PNG;
SVG-контейнер управляет только размещением, фоном и круговым отсечением.

Генератор совпадает с Flutter-репозиторием:

```powershell
npm install --prefix branding/toolchain --no-audit --no-fund
python -m pip install -r branding/toolchain/requirements.txt
python scripts/generate_brand_assets.py
```

`asset-manifest.json` содержит контрольные суммы каждого результата.

- `public/app-icon-master.png`: непрозрачный мастер 1024×1024, без
  нарисованного squircle. Собственный круг выбранного знака сохраняется.
- PWA `any`: 192/512; отдельный `maskable`: 192/512. Maskable имеет ровный
  ivory фон `#F5F1E8`, весь цветной круг помещается в радиус 40% ширины.
  См. [Maskable safe zone](https://web.dev/articles/maskable-icon).
- Apple touch: 180×180, непрозрачный RGB.
- Favicon PNG: 16/32/48/96, плюс ICO с теми же размерами. В 16/32 применяется
  одноцветная микроверсия на коричневом фоне: она сохраняет крест и сюжет,
  вместо потери деталей при уменьшении затенённой иллюстрации.
- `app-brand-96.png`: прозрачный круг для заголовка меню. Подключён в
  `NavigationDrawer.vue`; размеры и материалы самого меню сохранены.

Эмблема Марии на странице `About.vue` относится к парафии, а не к launcher,
и сохраняется. Старые `maria-menu-logo-*` не перезаписаны другим содержимым.

## Имена, палитра и установка

PWA name: `Каталіцкі малітоўнік`, short_name: `Малітоўнік`.
`start_url`, `scope`, origin и существующий способ определения PWA identity
не меняются. `id` не добавлялся поверх старого вычисляемого идентификатора.
В манифест добавлен второй размер maskable; прочие изменения — изображения
и ссылки на малые favicon. Существующий service worker получает новые
revision hashes автоматически при сборке VitePWA.

Основная палитра Web и литургические цвета не менялись: UI primary
`#6B4A32`, page `#F5F1E8`, rubric `#9B302A`. Нет динамического перекрашивания
иконки по литургическому дню. PWA splash формирует ОС/браузер из manifest,
icon и background_color; собственная native-анимация Web не обещается.
См. [Web app manifest](https://web.dev/articles/add-manifest).

## Проверено

- 11 PNG-экспортов: размеры и непрозрачность install surfaces.
- `npm run build`: успешная production-сборка и генерация service worker.
- 10 тестов `appearance.test.mjs` / `liturgical-theme.test.mjs`: все прошли.
- `node scripts/smoke_brand_install.mjs`: PWA реально установлена через
  Chrome DevTools в изолированный профиль и запущена как standalone;
  изображения, полученные через HTTP, совпали с публичными экспортами.
- Новая иконка в меню проверена в светлой и тёмной теме: naturalWidth 96,
  правильный src, без JavaScript page errors. 42 внешних запроса заблокированы;
  публичные и приватные Firestore-данные в этом тесте не читались.
- Результат и снимки: `validation/pwa-install.json`,
  `validation/pwa-installed-light.png`, `validation/pwa-installed-dark.png`.

Изолированное приложение удаляется при завершении теста. Профиль проверки
не является пользовательским браузерным профилем. Тест выполнен в Chrome
на Windows; Android PWA splash и iOS Add to Home Screen ещё требуют
устройственной проверки перед реальным release. Системные иконки уже
установленной старой PWA могут обновляться с задержкой браузера/ОС — проверка
новой установки не является обещанием мгновенной очистки этого кеша.

Изменения находятся на `codex/malitounik-brand-icons`, от Web HEAD
`cb35ee8daa938e4c3d67c7013f980fca8fe0f45f`. Исходная ветка с импортом контента
не переключалась и не очищалась. Публикуются Git-изменения для проверки;
deploy Firebase Hosting, merge в main и публикация в магазинах не выполнялись.
