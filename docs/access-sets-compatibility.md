# Access Sets V2 · совместимость старого доступа

Матрица описывает ожидаемое поведение после включения V2 и успешного копирования. Текущие пути проверены по исходникам и опубликованным Rules. Колонки V2 — критерии приёмки будущих PR. Версии и границы имеющихся доказательств приведены в [S0-аудите](access-sets-audit.md).

## Клиенты и пути чтения

| Клиент | Публичное | Legacy `priest` | Наборы V2 | Обязательная проверка |
| --- | --- | --- | --- | --- |
| Flutter до реализации священнического доступа, если ещё используется | Полные запросы к `prayers` и `prayerCategories` либо старый публичный bundle | По возможностям конкретной версии. Клиент, знающий только public, защищённый каталог не получает | Нет | Проверить доступный старый APK/IPA и ранее записанные публичные кеши. Наличие таких активных установок пока неизвестно. |
| Выпущенный legacy Flutter со Spark-доступом | Существующие Firestore-пути и публичный bundle/Hive | `priestDeviceGrants/{uid}` и обе `priestProtected*`. Есть прямой server `get` молитвы по ID | Нет | Android Play, прямой APK, iOS TestFlight/App Store отдельно. Ранее активированное устройство открывает старые молитвы тем же UID при обновлении без повторного ввода. |
| Ранее загруженный Web/PWA с legacy reader | Существующий Hosting JSON и offline cache | `priestDeviceGrants/{uid}` и обе `priestProtected*` | Нет | Открытая старая вкладка и установленный старый service worker переживают публикацию, перезапуск, revoke и обновление. |

| Flutter V2 | Существующий публичный bundle и обновления manifest | Аналогично Web V2, с сохранением package/bundle ID, именованного Auth app и secure storage | Да, по V2-профилю | In-place upgrade на Android/iOS, offline, background/resume, revoke, глубокая ссылка и синтетический APK/IPA scan. |

## Grant и ожидаемый результат

`Public` доступен во всех строках. Под «legacy клиентом» ниже понимается клиент, поддерживающий действующий Spark-доступ.

| Серверное состояние или действие | Legacy клиент | V2 клиент |
| --- | --- | --- |
| Гость или Anonymous UID без grants | Public | Public |
| Активный legacy grant, тот же UID | Public + зеркало priest | Public + canonical priest, без повторного ввода. Проверенное зеркало доступно до cutover или при backout. |
| Новый UID и действующий legacy-код | Штатный legacy batch, затем зеркало | Тот же legacy batch, затем `priest`. V2 grant не создаётся. |
| Legacy-код заменён | Ранее активный UID сохраняет доступ. Старый код не активирует новый UID. | То же, независимо от истории V2. |
| Отозванный legacy UID без V2 | Public. Статус отзыва остаётся. | Public. Запрещено восстанавливать `priest` одним лишь переносом. |
| Исторический grant с полем proof | Owner-get закрыт действующими Rules. Нужна проверка актуальных данных. | То же. Поведение старого клиента и V2 не должно обходить проверку состояния по grant. |
| Только V2, `allowedSets=['marian']` | Public, даже при возврате к старому клиенту с тем же UID | Public + marian. Закрыты canonical priest и зеркало. |
| Только V2, `allowedSets=['priest','marian']` | Public, legacy grant отсутствует | Public + оба набора из canonical. |
| Active legacy и V2 `['marian']` на одном UID | Public + зеркало priest | Public + priest + marian. Новый код добавляется без сброса старого доступа. |
| V2-код заменён или выключен, профиль активен | По legacy grant | Существующий V2 grant действует. Новая активация старым кодом отклоняется. |
| V2-профиль отключён, V2 grant отозван или профиль убрал набор | По legacy grant | Затронутое V2 право исчезает, оставшиеся независимые права сохраняются. Открытый reader и производные данные очищаются после потери серверного подтверждения. |
| Клиент выключает доступ при двух grants | Старый клиент может отозвать свой legacy grant | V2 сразу очищает экран и доставляет отзыв по обоим реестрам. После частичного сбоя продолжает с тем же UID. |
| Offline/reconnect либо revoke во время запроса | Контент закрыт при потере подтверждения в проверяемом Spark-клиенте | Public offline. Защищённое возвращается после проверки своего UID и прав с сервера. Поздние ответы отбрасываются. |
| Canonical/mirror расходятся или данные копии неполны | Старый путь остаётся согласованным в рамках условий writer и freeze | До cutover — прежний reader. После cutover — скрытие конфликтующей записи, сигнал администратору и сверка версии. |
| Потеря Auth state, очистка данных приложения или установка с несовместимой подписью | Восстановление прежнего UID не гарантируется | В репетиции обновления это проверяется отдельно от обычного upgrade. Secure storage не заменяет сохранённую Firebase Auth-сессию. |

Новый объект с несколькими итоговыми наборами, включая `priest`, доступен только поддерживающим V2 клиентам. Старые документы priest сохраняются в зеркале, а их повторная классификация не входит в начальный переход. Решение для смешанных наборов приведено в [контракте](access-sets-contract.md).

## Резервная копия и репетиция

1. После отдельного разрешения владельца и подтверждения квоты снять единый частный snapshot затрагиваемых путей. Включить четыре public/legacy content-коллекции, обе цели `protected*` с отметкой об отсутствии при пустой цели, `priestContentControl/state`, legacy settings/help/grants/claims и V2-пути при наличии. Зафиксировать границу времени/version, проект, git SHA, фактически активный ruleset и контрольные суммы. Для совместимых клиентов иметь точные старые артефакты, версии и сертификаты по каналам.
2. Снимок с lossless Firestore типами, server timestamps, ссылками, ID и `updateTime` хранится под ограниченным доступом вне Git и public. Данные для проверки Auth и claims держать отдельно. Разрешение установки не восстанавливает удалённую Auth-учётную запись, поэтому Auth UID и пользовательские сессии исключены из миграционных операций. На Spark план опирается на частный scoped backup и проверку квоты, доступность managed export не предполагается.
3. В локальном Emulator восстановить затрагиваемые документы в изолированную тестовую базу. Сверить count, состав ID, hash, типы, связи, renderer и права. Для Auth/grant/claim сценариев использовать синтетические UID и proof. Внешний отчёт содержит агрегаты и результат восстановления без идентификаторов и payload. Readback всех затронутых целей и восстановление предыдущей согласованной пары обязательны до разрешения на рабочее копирование.
4. Dry-run принимает этот снимок, строит неизменяемый план с digest и помечает отсутствующий охват, конфликты ID, возможные public-копии, неразрешимые связи, превышение лимитов и дрейф данных. Перед apply отдельный оператор сверяет scope, digest и updateTime/version текущего состояния, блокирует writers и проверяет, что защищённые Rules опубликованы. В отчёт выводятся только counts, результат parity и признак сохранения legacy settings/claims/grants.

## Откат и удаление моста

| Момент | Действие по отдельному разрешению |
| --- | --- |
| До открытия V2, включая частичный copy | Оставить старый reader и зеркало обслуживать `priest`, удержать lock затронутых писателей. По журналу и precondition продолжить тот же план либо восстановить только изменённые canonical цели до preimage. Copy не меняет legacy-тексты и grants. |
| Canonical уже читается, обнаружено нарушение parity | Закрыть затронутую выдачу и соответствующие записи, сохранить валидную пару для старых клиентов. Восстановить согласованную version/пару проверенным restore. При необходимости вернуть Web Hosting к проверенной legacy-сборке. Старый PWA проверить отдельно. |
| После выдачи V2 grants или релиза Flutter V2 | Сохранить V2 записи и совместимые Rules для уже обновившихся приложений. Остановить новую выдачу, если этого требует инцидент. При ошибке доступа закрыть затронутые наборы, исправить Rules или контент вперёд и выпустить исправление по каналу распространения. Мобильный downgrade может быть недоступен. |
| Ошибка Rules | Использовать последнюю известную безопасную конфигурацию, совместимую с уже выданными V2 grants, либо целевое закрытие V2 путей. Проверить public/legacy `get/list` и deny закрытых путей. Старая permissive конфигурация не считается приемлемым rollback. |

Удаление моста — отдельный будущий PR и операция. Нужны принятый минимум версий по Web/Android/iOS и всем мобильным каналам, измерение зависимых читателей за заранее согласованное окно, период уведомлений и обновления, доказательство отсутствия зависимостей, резервная копия с проверенным restore и план отката. Сам факт публикации V2 ничего из этого не подтверждает. Остановка legacy-активации согласовывается отдельно и не должна отзывать выданные grants.
