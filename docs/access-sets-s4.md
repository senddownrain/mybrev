# Access Sets V2 · Web-каталог и writer S4

База [PR #320](https://github.com/senddownrain/mybrev/pull/320) зафиксирована на
`56d398c2c20d505d9476e267bd1b29b1ecf77991`. Ветка S4 использует тот же wire-контракт.

## Чтение и границы сессии

Публичная выдача строится из Hosting JSON и доступна независимо от подтверждения
установки. Закрытый слой использует только Firestore Lite и серверный S1 gateway.
`createAccessSetsCatalogSession` обходит индексы страницами по 25 ID, с одним
активным запросом списка и общим пределом в четыре одновременных запроса. Один
`get` на пару (тип, ID) обслуживает выдачу и прямую ссылку в пределах поколения.
Отказ отдельного `get`, отсутствие документа, неверная привязка к индексу,
неизвестный родитель и несовместимое членство исключают результат из каталога.

`installPrayerCatalogEntitlements({ confirm, subscribe })` в
`src/services/prayerCatalogAccess.js` подключает S2.

- `confirm()` асинхронно возвращает подтверждённое сервером
  `{ mode: 'canonical', uid, allowedSets, gateway }` либо `null`.
  `allowedSets` включает `priest` при действующем legacy grant. `gateway`
  реализует S1 `listIds` и `readContent` на той же установке.
- Для `legacy` провайдер возвращает
  `{ mode: 'legacy', legacyActive: true, readLegacy(assertCurrent) }` после
  проверки grant. `readLegacy` возвращает `{ prayers, categories }` из
  авторизованного зеркала и между запросами вызывает `assertCurrent()`.
  Режим `suspended` даёт публичную выдачу.
- `subscribe(invalidate)` возвращает отписку. S2 вызывает `invalidate`
  синхронно при смене UID, режима, подтверждённых прав, ревизии entitlements,
  ожидающем отзыве или потере подтверждения. Новый доступ применяется после
  повторного `confirm()`. До установки S2 работает прежний legacy grant.
- Offline, скрытие страницы и уход в background очищают память самостоятельно.
  Ошибка сети, квоты или списка также закрывает защищённую выдачу. Ответы
  предыдущего поколения отбрасываются. Избранное V2 существует в памяти
  поколения, а прежние настройки избранного public/legacy сохраняются.

## Запись и парность

Доверенный writer находится в `scripts/lib/access-sets-v2-writer.mjs`.
`bindCanonicalCatalogCallable({ db, onCall, HttpsError })` привязывается
к выбранному транспорту с проверенным Firebase Auth и App Check. Серверный
Admin SDK инициализируется с `useBigInt: true` для целых Firestore int64.
Доступ получают `superadmin` и `admin` с `accessSetsV2: true`.
Production endpoint не зарегистрирован в этом PR.

S3 передаёт в `createCanonicalPrayerSaveApi(invoke)` аутентифицированный вызов
и работает с массивом правок `{ kind, id, action, patch }`. `kind` принимает
`prayers` или `categories`, `action` принимает `create`, `update` или
`delete`. `patch.accessSets` задаёт собственные альтернативы.
Пустой список снимает собственное ограничение и сохраняет наследование.

1. `preview(edits)` проверяет исходное состояние, строит план и возвращает
   версию, digest, число операций и вердикт парности.
2. `save(edits, preview)` перечитывает версию, роль, режим и актуальные
   документы в транзакции. Точный digest связывает сохранение с просмотренным
   планом. Ошибка `content-snapshot-drift` требует свежего preview.
3. `verify(preview)` подтверждает версию и итоговый digest, в том числе если
   клиент потерял ответ после коммита.

Прямые SDK-записи в canonical и ID-индексы запрещены. Старый редактор в
`legacy` продолжает использовать прежний writer. При `canonical` или
`suspended` Rules блокируют этот путь записи и сохраняют legacy-чтение.
Публикация черновиков остаётся на legacy writer в режиме `legacy`. Для
cutover требуется связать её с доверенным writer в интеграции S3, сохранив
проверки черновика, его версию и аудит публикации в той же транзакции.

План применяет OR внутри собственных наборов и AND между ограничениями
предков, тегов, ручных ссылок и `categoryId`/`categoryIds`. Публичная связь
нейтральна. Неизвестные связи или наборы, циклы, пустое пересечение, расхождение
хешей и потерянный индекс блокируют запись. Для итогового `['priest']`
writer держит точную пару канонического payload и legacy-зеркала.
`marian` и смешанные записи зеркала не получают. Публичная ручная связь с
защищённой молитвой хранится на самой закрытой молитве.

`catalogContentHash` вычисляет SHA-256 от стабильного типизированного
представления общего payload. Он исключает ID документа и четыре поля V2.
Даты, геоточки, bytes, ссылки и int64 проверяются с сохранением SDK-значений.
План ограничен 400 записями с версией, 7 МБ оценки транзакции, 900 КБ оценки
документа и 2 500 чтениями сканирования. Firestore дополнительно проверяет
фактический protobuf и индексы. Ошибка до коммита оставляет исходное состояние
целиком. Откат из сохранённого preimage проверяет итоговый digest и версию,
восстанавливает данные атомарно и увеличивает версию.

S5 может использовать `readCanonicalCatalogSnapshot` и `assertCatalogParity`
для приватного snapshot dry-run. Снимок должен явно покрывать пустые
коллекции и индексы. Первые копии priest должны сохранять ID, payload и
итоговый `['priest']`. Снимок S5 должен зафиксировать orphan-индексы под
отсутствующим set-документом и проверить типы, которые не покрывал старый
JSON-формат снимка. Реальный copy, его журнал и подтверждение открытия
canonical остаются отдельными операциями.

## Spark и публичные артефакты

Тест в Emulator считает фактические запросы gateway. Для трёх документов и
двух наборов, с одним пересечением и страницей 2, он ожидает 6 запросов к
индексу, 8 чтений индекса с учётом пустых страниц и 3 канонических `get`.
Открытие уже прочитанной прямой ссылки добавляет 0 запросов. Наблюдаемая
конкурентность в этой фикстуре равна 2, предел клиента равен 4.

По веткам S1 Rules верхняя оценка составляет до 5 различных зависимых
документов на запрос списка и до 6 на канонический `get`. Это до
`8 + 3 + 6×5 + 3×6 = 59` чтений для фикстуры вместе с данными.
Оценка ограничивает стоимость сверху. Emulator не измеряет счёт проекта.
Запросы S2 для подтверждения сессии считаются отдельно. При 100 ID на
каждую пару из двух типов и двух наборов получается 20 страниц
и 404 чтения индекса с учётом пустых завершающих страниц. При полном
пересечении наборов это до 1 904 чтений вместе с 200 каноническими
`get` и Rules, при непересекающихся индексах до 3 304. Квота останавливает
очередь без автоматических повторов. См. [Firestore pricing](https://firebase.google.com/docs/firestore/pricing#cloud-firestore-security-rules)
и [лимиты Rules](https://firebase.google.com/docs/firestore/security/rules-conditions#access_call_limits).

Hosting JSON и Flutter bundle/manifest отбрасывают закрытый текст,
названия, превью и записи из закрытых путей, включая ошибочную публичную
копию с тем же ID. Flutter bundle сохраняет прежние ID ручного членства,
которые ссылаются на legacy-зеркало и нужны старому клиенту. Отчёт по
закрытой молитве не добавляет контекст с текстом, заголовком или ID.
Firestore остаётся `NetworkOnly` в service worker. Запись в публичные
пути требует отдельной публикации по
[регламенту контента](app-content-distribution.md). Ранее опубликованные
копии нельзя отозвать атомарным переносом из Firestore, поэтому при закрытии
ранее публичного материала S8 также оценивает сохранённые клиенты и артефакты.

## Интеграция и воспроизведение

- S2 подключает серверный провайдер. S3 подключает формы, публикацию
  черновиков и утверждённый транспорт writer. Окружение Spark не меняется
  этим PR. Release gate [#317](https://github.com/senddownrain/mybrev/pull/317)
  и стек [#319](https://github.com/senddownrain/mybrev/pull/319) →
  [#318](https://github.com/senddownrain/mybrev/pull/318) →
  [#320](https://github.com/senddownrain/mybrev/pull/320) остаются зависимостями.
- S5 репетирует copy, parity и restore. S7 сверяет поведение Web и Flutter.
  S8 сверяет развёрнутые Rules, канальную матрицу, утверждённый запуск writer
  и только после этого открывает canonical.
- Локальные проверки: `npm run test:priest`, `npm run test:priest:rules`,
  `npm run test:access-sets-v2`, `npm run test:prayer-normalization`.
  S4 Emulator — `firebase emulators:exec --only auth,firestore --project demo-rules "node --test tests/access-sets-v2-writer-firestore.test.mjs"`.
- После `npm run build` переменная `S4_DIST_SCAN=1` включает проверку
  `dist` командой `node --test tests/access-sets-v2-public.test.mjs`.
  Тот же тест запускает `content:manifest` в dry-run на синтетическом
  snapshot. Браузерная проверка с синтетическим провайдером запускается
  командой `node scripts/smoke-access-sets-v2-catalog.mjs`.
