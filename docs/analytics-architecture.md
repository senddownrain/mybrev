# Аналитика: архитектура (бесплатная, local-first, сеть выключена)

Статус: проект. **Ни один компонент приёма не создан, не развёрнут и не включён.** Серверной
аналитики нет, endpoint не существует. Контракт — `docs/analytics-contract.md`, правовые условия —
`docs/analytics-privacy.md`.

## 1. Ограничения, определяющие выбор

Spark остаётся Spark (без Blaze, BigQuery, платных SDK); производительность чтения важнее
телеметрии; нет идентификаторов; сеть выключена по умолчанию; при исчерпании лимитов — корректная
деградация, а не обещание «0 € при любой нагрузке».

Факт эксплуатации на момент работы: суточная квота production Firestore исчерпана (до ~07:00 UTC
2026-10-14). Любое решение, делящее квоту Firestore с чтением контента, ломает продукт.

### 2.1 Почему нельзя писать каждое событие в Firestore Spark

1. **Квота.** 20 000 записей/сутки и 50 000 чтений/сутки на проект (F8) — общие с чтением
   контента приложения. Один сеанс чтения даёт десятки событий; тысячи читателей в день исчерпали бы
   записи, а исчерпание квоты чтения сегодня уже случилось по другим причинам. Аналитика
   не должна быть способна ломать чтение.
2. **Нужна авторизация или открытые правила.** Правила Firestore не могут ограничить частоту по IP
   (`docs/priest-access.md`: «В Spark Rules нет серверного лимита попыток по IP»). Открытая запись —
   спам и переполнение; Anonymous Auth создаёт UID — это постоянный идентификатор (запрещён),
   плюс заметно увеличивает квоту Auth.
3. **Горячий документ.** Общий счётчик `increment` ограничен ~1 записью/с на документ; шардирование —
   рост записей и стоимости.
4. **Хранение без стандарта удаления.** Резервные копии/экспорты Firestore содержат всё.
5. **Один пакет — одна запись** лучше, но остаётся спамом и тратит ту же квоту.

### 2.2 Почему не Cloud Functions в Firebase

Нужны Blaze (F8, вывод из таблицы). Репозиторий уже содержит `functions/` (Argon2) — это архив
прежней реализации доступа священников, не используется и не должен деплоиться; поэтому
«существующая инфраструктура» там **отсутствует**: ни один деплой Functions не сделан, Blaze не
включён. Каталог не трогается.

## 3. Выбранная архитектура

```text
 приложение (web/Android/iOS)
   in-memory счётчики + бакеты  ──flush при hidden/pause──▶  локальное хранилище (≤14 суток, ≤64 КиБ)
        │                                                             │
        │  analytics_network_enabled == false (по умолчанию)          │ только если ВСЕ условия §12 контракта
        ▼                                                             ▼
   конец: ничего не отправляется                       POST /v1/aggregates  →  Cloudflare Worker  →  D1 (agg_cells)
```

### 3.1 Режим по умолчанию (единственный, который можно считать выбранным)

Локальное измерение: счётчики в памяти, сброс в локальное хранилище на `hidden`/`pause`, нет ни
запросов, ни таймеров, ни очередей сети. При `analytics_network_enabled=false` отправитель
не создаётся. Это единственная часть, не зависящая от внешнего решения.

### 3.2 Кандидат для сети: Cloudflare Workers + D1 (Free) — гипотеза

Проверенные квоты (официальные страницы, 2026-10-14):

| Ресурс | Free-лимит | Поведение при превышении |
|---|---|---|
| Worker запросы | 100 000/сутки | ошибка 1027; fail-open/closed по режиму маршрута |
| CPU на запрос | 10 мс | запрос прерывается |
| Subrequests/D1-запросов на вызов | 50 | ошибка |
| D1 строк записано | 100 000/сутки | запросы к D1 возвращают ошибку лимита до 00:00 UTC |
| D1 строк прочитано | 5 млн/сутки | то же |
| D1 размер | 500 МБ/БД; 5 ГБ аккаунт; 10 БД | вставки блокируются |
| Rate Limiting binding | периоды 10 или 60 с, счётчик **локален для площадки** Cloudflare, eventually consistent; доступность на Free — **НЕ ПОДТВЕРЖДЕНО** страницей | — |

Что из этого следует (расчёты — оценки, подлежат замеру в промпте 02, не обещания):

- Узкое место — **записи D1**, не запросы Worker. Если один upsert ячейки считается одной
  записью строки (и ещё записью индекса — `НЕ ПОДТВЕРЖДЕНО`), то пакет из ~20 ячеек стоит 20–40
  записей, и дневной лимит 100 000 исчерпывается примерно на 2 500–5 000 пакетах в сутки.
  Следовательно, один пакет на устройство в сутки покрывает ~2–5 тыс. активных устройств в день,
  затем приём деградирует.
- Деградация корректная: при ошибке лимита Worker отвечает `204` и ничего не пишет (клиент не
  повторяет; данные дня теряются — для статистики допустимо); чтение приложения не зависит от ответа.
- Предохранитель: строка в D1 `day_budget(day, packets)`; сверх бюджета Worker отвечает `204`
  без записи, не расходуя остаток квоты. Бюджет задаётся переменной, kill switch — переменная
  `ANALYTICS_ENABLED=false` → ответ `410`.
- Ёмкость при росте измеряется (после включения) числом отброшенных пакетов в `day_budget`;
  при постоянной нехватке — сокращать частоту клиентов (раз в 7 суток), число ячеек (слияние
  `er`/`sd`), а не платить молча. Переход на Paid — отдельное решение владельца.

### 3.3 Защита endpoint без идентификаторов

Нет ключей пользователя — значит нельзя отличить «человека» от скрипта. Меры снижают ущерб, не
устраняют фальсификацию:

1. Строгая схема (`validatePacket` на сервере): неизвестные поля/значения — `400`; тело ≤ 16 КиБ;
   ячеек ≤ 200; `n` ≤ 10 000; допускается только `schema_version` из белого списка; `content_id` — из
   серверной копии публичного инвентаря (закрытые материалы не пройдут).
2. Лимит суммарного `n` на пакет (напр. ≤ 5 000 открытий в сутки на устройство) — отсекает
   тривиальную накрутку одним запросом.
3. Дневной бюджет пакетов (предохранитель выше) и глобальный бюджет записей.
4. Rate limit по площадке/маршруту: либо Rate Limiting binding (если доступен на Free),
   либо правила WAF/Rate limiting rules на уровне Cloudflare (доступность на Free-плане для нашей
   конфигурации — `НЕ ПОДТВЕРЖДЕНО`). Ключ по IP использовать только в памяти счётчика Cloudflare, без
   записи в D1; сам факт обработки IP — вопрос D-01/D-05.
5. CORS: для web — только origin(ы) приложения; для нативных приложений Origin нет, поэтому CORS —
   не защита, а удобство.
6. Публичный «ключ приложения» не является секретом и не вводится как мнимая защита.
7. Отчёты строить с отсечением выбросов и подавлением малых групп (контракт §11); доверие к
   данным — «ориентир», не учёт.
8. Нет журналов: Workers Logs/Observability выключены, `console.log` пакетов запрещён; Cloudflare как
   транспорт всё равно видит IP — **это остаточный риск**, обязательный вопрос к D-01/D-05.

### 3.4 Что остаётся неподтверждённым в F-варианте

Правовой статус пакета (D-01), юрисдикция Cloudflare как обработчика (D-05), доступность rate-limit
на Free, учёт строк индекса в «rows written», срок хранения логов Cloudflare на периметре,
согласие для iOS (D-03). Пока это не закрыто, F — **гипотеза**, а не решение.

### 3.5 Полный тракт для проверки «после отправки не анонимно»

| Звено | Что может раскрыть | Мера в проекте |
|---|---|---|
| Транспортный запрос | IP, время, User-Agent | Не логировать; не хранить; D-01/D-05 |
| URL | путь `/v1/aggregates` без параметров | Нет query-строк с данными |
| CDN/прокси Cloudflare | edge-логи у провайдера | вне контроля, `НЕ ПОДТВЕРЖДЕНО` |
| Worker | логи, исключения | выключены, не логировать тело |
| D1 | строки `agg_cells` | только агрегаты, без raw |
| Резервные копии D1 / Time Travel | история состояний | Time Travel хранит историю БД — срок и удаление `НЕ ПОДТВЕРЖДЕНО` |
| Внешние обработчики | Cloudflare | договор не оформлен |
| Отчёты | малые группы | порог 10 |

## 4. Поведение при закрытом сетевом шлюзе (что работает)

| Функция | `analytics_network_enabled=false` |
|---|---|
| Чтение, прокрутка, навигация, офлайн | не зависят от аналитики |
| Подсчёт визитов/метрик в памяти | работает, если включён локальный режим (отдельный релиз, D-10) |
| Запись в локальное хранилище | работает (≤14 суток, ≤64 КиБ), без сети |
| Сеть/очередь/таймер отправки/конфиг | **не создаются**; ни одного запроса |
| Ручной экспорт | возможен после реализации (вне этого этапа) |
| Отчёты/дашборд | нет данных на сервере; не проектировались |

## 5. Существующий Sentry

Sentry уже может собирать навигационные транзакции (10%) и записи сессий (10%), если в production
задан DSN (`НЕ ПОДТВЕРЖДЕНО`). Аналитический контракт его **не использует, не расширяет и не
дублирует**; решение D-08.
