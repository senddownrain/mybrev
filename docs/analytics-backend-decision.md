# Аналитика: выбор серверной агрегации (только план), 2026-10-16

**Ничего не развёрнуто и не включено.** Нет живого endpoint, нет флагов отправки, нет Cloud Functions/Blaze, нет
админки и дашборда, нет analytics-enabled production. Документ готовит решение владельца; отправка начинается
только после положительного юридического заключения (D-01). Решения D-01…D-10 — в `docs/analytics-privacy.md` §6.

Текущее состояние: D-10 = B (локальный счёт в тестовых сборках), D-04 = (c) региона нет, всё `UNKNOWN`.
Сетевой передачи нет ни в вебе, ни во Flutter.

## 1. Что нужно от сервера (минимум)

Принимать **готовые агрегатные пакеты** контракта v2 (`schema_version, day (UTC), platform, app_version major.minor,
region=UNKNOWN, cells[]`) и складывать счётчики по ключу ячейки. Без user/device/session ID, без истории переходов,
без тела текста. Пакет уже содержит только счётчики `n`; сервер не должен ничего достраивать.

## 2. Что раскрывается самим фактом запроса (нельзя считать «агрегаты автоматически анонимны»)

- **IP-адрес и время запроса** видит транспорт (провайдер, CDN/Workers, его логи) даже если мы их не сохраняем.
  IP — потенциально персональные данные; в сочетании с данными о молитвенной практике (категория «религиозные убеждения»,
  ст. 9 GDPR; закон РБ 99-З) вопрос открыт — это D-01.
- **Малые группы:** ячейка вида «платформа × версия × день × редкий материал × n=1» почти идентифицирует одного человека.
  Нужен порог публикации (k-анонимность: не показывать/не хранить раздельно ячейки с n < k, например k=5; значение — решение).
- **Повторные пакеты:** без ID установки сервер не отличит повтор от нового пакета; клиент может отправить пакет
  дважды (сбой подтверждения) → завышение. Без ID защиты от повтора нет; допустим только идемпотентный ключ пакета,
  **который сам становится идентификатором**, поэтому его надо ограничивать (случайный на пакет, не на установку, не хранить).
- **Накрутка:** любой может слать поддельные пакеты. Анонимность и защита от накрутки конфликтуют; допустимый уровень —
  rate limit по IP на периметре без записи IP, потолки `n` на ячейку и на пакет, валидация по инвентарю публичных ID.

## 3. Кандидат: Cloudflare Workers + D1 (Free)

Лимиты по публичной документации Cloudflare, **проверить на дату решения** (в этой среде не сверялись с живой страницей):
Workers Free — порядка 100 000 запросов/сутки и ~10 мс CPU на запрос; D1 Free — порядка 5 млн прочитанных строк/сутки,
100 000 записанных строк/сутки, ~5 ГБ хранилища. Из лимитов вытекает оценка:

- Одна ячейка = одна upsert-запись (строка в `cell_counts`), пакет ≈ 15–40 ячеек (в наших прогонах 16–36).
- Ёмкость записи: 100 000 строк/сутки ÷ ≈ 30 ячеек ≈ **~3 000 пакетов/сутки** на Free при записи «ячейка = строка».
  Это потолок с запасом на индексы (индексы тоже считаются записями) — реально меньше. Для малой аудитории достаточно,
  для роста нужно пакетное объединение (один пакет → одна запись JSON в «сырую» таблицу и ночная свёртка) или платный план.
- Хранилище: 395 суток × ячеек/день. При ~2 000 уникальных ключей в день ≈ 0,8 млн строк за срок хранения ≈ десятки МБ — запас большой.
- Чтения: админка не планируется; экспорт — ручной запрос раз в сутки/неделю.

**Fail-closed:** переключатель в Worker (`INGEST_ENABLED=false` по умолчанию) и в клиенте (флаг сборки). Если Worker
недоступен, клиент **молча отбрасывает** (локальный буфер не растёт сверх 64 КиБ / 14 суток), UI не зависит от успеха.

### Схема (черновик, SQL не применялся)

```sql
-- одна строка = один счётчик ячейки за день; никаких идентификаторов
CREATE TABLE cell_counts (
  day            TEXT NOT NULL,      -- UTC YYYY-MM-DD
  platform       TEXT NOT NULL,      -- web | android | ios
  app_version    TEXT NOT NULL,      -- major.minor
  region         TEXT NOT NULL,      -- UNKNOWN (до решения D-04)
  event          TEXT NOT NULL,      -- screen_view | text_read | feature_use | catalog_open | measurement_error
  section        TEXT,
  content_id     TEXT,               -- только из публичного инвентаря
  metric         TEXT,               -- fv | er | sd
  bucket         TEXT,
  feature_id     TEXT,
  catalog_id     TEXT,
  error_id       TEXT,
  n              INTEGER NOT NULL,
  PRIMARY KEY (day, platform, app_version, region, event, section, content_id, metric, bucket, feature_id, catalog_id, error_id)
);
-- удаление по сроку хранения (D-06, предложение 395 суток)
-- DELETE FROM cell_counts WHERE day < date('now', '-395 day');
```

Тестовый mock-обработчик (офлайн, без публикации): принимает пакет, прогоняет те же `validatePacket` и инвентарь ID, что и
клиент, отвергает неизвестные поля, потолок `n` и размер; можно написать как Node-тест против фикстур v2 — **не сделано**, только предложение.

## 4. Альтернативы (если правового основания для Cloudflare нет)

| Вариант | Плюсы | Минусы / блокеры |
|---|---|---|
| A. Без сервера: ручной экспорт локального буфера из тестовых сборок (QA-тестеры) | нет IP, нет сети, нет юридического вопроса передачи | малая выборка, нет данных из публичной аудитории; работает уже сейчас |
| B. Self-hosted endpoint (VPS в выбранной юрисдикции, SQLite/Postgres) | контроль над логами и юрисдикцией, нет квот | эксплуатация, TLS, обновления, DDoS, стоимость, ответственность за безопасность |
| C. Cloudflare Workers + D1 | дёшево, без сервера, маленькая поверхность | юрисдикция/DPA и логи (D-05), лимиты Free, зависимость от вендора |
| D. Сторонняя privacy-first аналитика (self-host Plausible/Umami) | готовые защита и отчёты | события молитв выходят за их модель; всё равно IP и юрисдикция; другая схема данных |
| E. Firebase Analytics / GA4 / Firestore-счётчики | быстро | **исключено**: ID устройства, рекламные категории, требования Apple/Google, Firestore-квота уже была исчерпана; не использовать |

Рекомендация к обсуждению: **A сейчас**, **C или B** только после D-01/D-05; **E не рассматривать**.

## 5. Sentry веба (только анализ, конфигурация не менялась)

`src/plugins/sentry.js`: включается только в production при заданном `VITE_SENTRY_DSN`; `tracesSampleRate 0.1`;
`replaysSessionSampleRate 0.1`, `replaysOnErrorSampleRate 1.0`; `browserTracingIntegration({router})`. Задан ли DSN в production,
**не проверялось** (секрет не читался). Если задан, уже сегодня собираются навигация по реальным путям (`/prayer/<id>`, `/songs/…`,
`/bible/…`) и 10% записей сессий — это более подробная телеметрия, чем контракт аналитики, с IP транспорта. Варианты
минимизации (решение владельца D-08): (a) replay и трассировка в `0`; (b) оставить ошибки, добавить `beforeBreadcrumb`/`beforeSend`
с параметризацией путей (`/prayer/:id`) и `maskAllText`/`blockAllMedia` для replay; (c) отключить Sentry. Рекомендация: (b) + replay=0.
Это не блокирует локальный режим, но должно быть решено до любого разговора о сетевой аналитике.

## 6. Чеклист разрешения сетевой отправки (по платформам и регионам)

Включать отправку для сегмента можно только когда **все** пункты строки закрыты. Сейчас не закрыт ни один.

| Платформа | Регион | Условия | Состояние |
|---|---|---|---|
| Web | UNKNOWN (единственный режим до D-04) | D-01 (заключение), D-05 (инфраструктура), D-06 (срок), D-07 (политика), D-08 (Sentry) | закрыто 0 из 5 |
| Web | BY | + D-02 (регистрация оператора ПД, НЦЗПД), D-03 (форма согласия) | закрыто 0 |
| Web | OTHER | + проверка GDPR/ePrivacy для EEA/UK (ст. 9, хранение/доступ на устройстве) | закрыто 0 |
| Android | UNKNOWN/OTHER | как Web + D-09 (Play Data safety), политика Google Play | закрыто 0 |
| Android | BY | как Android + D-02, D-03 | закрыто 0 |
| iOS | UNKNOWN/OTHER | как Web + **явное согласие в приложении по Apple 5.1.1(ii)** (даже для анонимных данных), отзыв в настройках, `PrivacyInfo.xcprivacy`, App Privacy | закрыто 0; **реализация согласия не начата, правила не сверялись с живыми страницами Apple** |
| iOS | BY | iOS-условия + D-02, D-03 | закрыто 0 |

## 7. Явные решения владельца (список)

1. **D-01** заказать юридическое заключение (персональные данные? религиозные убеждения? согласие?) или отказаться от сетевой аналитики.
2. **D-02** регистрация оператора персональных данных (РБ) — нужна ли.
3. **D-03** форма согласия (opt-in по умолчанию «выкл»; на iOS обязателен).
4. **D-04** регион: оставить «региона нет» (`UNKNOWN`) или определять (локальная эвристика / страна от CDN без записи).
5. **D-05** инфраструктура: Cloudflare Workers+D1 / иное / «нет сервера» (вариант A).
6. **D-06** срок хранения (предложение 395 суток) и политика удаления.
7. **D-07** политика конфиденциальности (web, Play, App Store): текст и публикация.
8. **D-08** судьба Sentry: оставить / ужесточить (рекомендация (b) + replay=0) / отключить; и подтвердить, задан ли DSN в production.
9. **D-09** Data safety и App Privacy под фактический режим — перед релизом с отправителем.
10. **D-10** (принято: вариант B) — менять только если решите шире.
11. Новое: порог малых групп k (например 5) и лимиты `n` на ячейку/пакет; идемпотентный ключ пакета — нужен ли.
12. Разрешения на запуск: замеры производительности на устройстве/эмуляторе, чтения живых данных Firestore для проверки на реальных материалах.

Что не делается без этих решений: никакого живого API, никакого отправителя в клиентах, никакой админки, никаких записей в Firestore.
