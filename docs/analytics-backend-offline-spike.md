# Offline-прототип приёма аналитики v2 (spike)

**OFFLINE PROTOTYPE ONLY / NETWORK NOT APPROVED.** Дата 2026-10-17, ветка `spike/analytics-v2-backend-offline` от `origin/main` `e1bfa8a`. Каталог `experiments/analytics-ingest/`. Никакого развёртывания, реальной D1, `wrangler deploy`, `firebase deploy`, живых запросов, отправителя в клиентах, изменений Sentry и privacy-настроек, Firestore-записей. Прототип не разрешает собирать данные.

## 1. Инварианты (из кода, не изменены)
Белый список взят из `src/utils/analytics/contract.js` (`validatePacket`, `LIMITS`) и `tests/fixtures/analytics-contract-v2.json` (SHA-256 `af2d0176…`, совпадает с Flutter `main`). Пакет: `{schema_version=2, day (UTC), platform, app_version major.minor, region, cells[]}`; ≤ 16 КиБ, ≤ 200 ячеек, `n` 1..10000, `content_id` только из `public-inventory.json` (750). Без URL, referrer, заголовков, UA, IP, точных времён, ID пользователя/установки/сессии, текстов молитв и поисковых строк. Интерфейс `handleIngest` вообще не принимает заголовки.

## 2. Архитектура
```
request {method, bodyText} ──► kill switch (INGEST_ENABLED, default OFF → 503, ничего не читается)
   ├─► method POST? (405)  ├─► ≤ 16 KiB? (413)  ├─► JSON? (400)  ├─► schema_version == 2? (426)
   ├─► validatePacket + public IDs (400, только число ошибок)  ├─► region ∈ {UNKNOWN} (400)
   ├─► day ∈ [today−2, today] UTC (400)  ├─► normalize: ключ ячейки = JSON-массив из 12 полей
   └─► storage.addCounts: одна транзакция на пакет, дневной бюджет записей (503 при превышении), upsert n = n + :n
```
Ответ `204` без тела при успехе; клиент не зависит от ответа (drop-on-uncertainty). Логи: только фиксированные коды (`CODES`) и числа, содержимое пакета и заголовки не логируются.

## 3. Схема хранения
`cell_counts(cell_key TEXT PRIMARY KEY, n INTEGER) WITHOUT ROWID` + `daily_budget(day, rows_written)`. `cell_key` = `["2026-10-17","web","4.5","UNKNOWN","text_read","prayers","prayer:…","fv","5_15s","","",""]`. Вторичных индексов нет (проверено тестом): **одна запись строки на upsert**; retention — удаление диапазона первичного ключа `cell_key < '["<cutoff>"'` (ключ начинается с дня). Сырой пакет, заголовки, IP, UA, cookie, точные времена, отпечатки не хранятся.

## 4. Варианты и выбранные компромиссы
| Вариант | За | Против | В прототипе |
|---|---|---|---|
| A. Без сервера, ручной экспорт | нет IP/сети | малая выборка | остаётся рабочим вариантом сейчас |
| B. Cloudflare Workers + D1 Free | дёшево, нет сервера | Edge видит IP и время; юрисдикция/DPA не решены; лимиты Free | схема и ядро совместимы; не развёрнуто |
| C. Свой endpoint | контроль логов | эксплуатация, DDoS | ядро переносимо (чистые функции) |
| Агрегация в памяти/очередь вместо записи на каждый пакет | меньше записей D1 | сложность, потеря при сбое | **не реализовано**, указано как способ снижения стоимости |

Выбор: чистое ядро без SDK + две реализации хранилища (память, локальный SQLite); адаптер D1 не писался.

## 5. Стоимость (лимиты проверены 2026-10-17)
Cloudflare: Workers Free — 100 000 запросов/сутки, 10 мс CPU на HTTP-запрос, 50 subrequests (страница обновлена 12.10.2026); D1 Free — 5 млн чтений/сутки, **100 000 записей строк/сутки** (индексы добавляют записи), 5 ГБ; при превышении D1 останавливает запросы (источники: https://developers.cloudflare.com/workers/platform/limits/ и /d1/platform/pricing/). Модель: один upsert на ячейку на пакет, дневной стоп на 80 000 (80 %).

| Пакетов/сутки | ячеек в пакете | записей строк/сутки | в бюджете (80 000)? |
|---|---|---|---|
| 100 | 20 | 2 000 | да |
| 1 000 | 20 | 20 000 | да |
| 3 000 | 20 | 60 000 | да |
| 3 000 | 30 | 90 000 | **нет, BLOCKED** (макс. при 30 ячейках ≈ 2 666 пакетов/сутки) |
Допущение «1 upsert = 1 записанная строка» **не проверено на биллинге D1** (без развёртывания проверить нельзя): `NOT VERIFIED`. Строгого ограничения бюджета нет, пока не доказан учёт записей D1; поэтому при нехватке бюджета ответ 503 и потеря пакета — осознанная деградация, не рост счёта (Free не списывает деньги, а останавливает запросы).

## 6. Безопасность и абьюз
- Два fail-closed выключателя: клиентский build gate (сейчас `false`, `ANALYTICS_NETWORK_DEFAULT`) и `INGEST_ENABLED=false` на сервере: **любой запрос получает 503 `ingest_disabled`** без разбора тела и без записи (503, а не 410: «временно выключено», клиент молча отбрасывает).
- Нет публичного чтения статистики и админ-endpoint; нет токенов; секретов в приложениях нет. Чтение — только будущий отдельный авторизованный контур.
- Спуфинг: страна/IP из заголовков не читаются; `region` из тела допускается только `UNKNOWN` (до D-04). Любой может слать поддельные пакеты: защита от накрутки слабая по определению (без ID): потолки `n`, число ячеек, дневной бюджет и валидация по whitelist ограничивают ущерб, но не исключают его.
- Видимость IP: инфраструктура периметра (Cloudflare/хостинг) видит IP и время запроса, даже если приложение их не хранит. Это требует правового решения (D-01, D-05).

## 7. Дедупликация (НЕ решена)
Без идентификатора exactly-once невозможна: повтор пакета считается дважды (тест это фиксирует). Варианты: (1) **at-most-once / drop-on-uncertainty** на клиенте (не повторять при сомнении) — недосчёт вместо перерасчёта, приватно; (2) временный случайный токен пакета со списком токенов на сервере на 1–2 суток — защищает от повтора, но токен = идентификатор пакета, его надо хранить и он создаёт риск связывания; (3) подписанные токены/attestation — нужны секреты и платформенные API, противоречат «без секретов в приложении». Рекомендация: (1) на старте, измерять разницу, к (2) возвращаться только по решению владельца.

## 8. Малые группы
Подавление на чтении (`report.mjs`): ячейки с `n < k` (k = 5 как проектное решение, 10 — вариант) не попадают в отчёт. Это не юридическая анонимизация; единичный пакет всё равно может содержать чувствительную комбинацию, а сервер его получил.

## 9. Как тестировать без сети
`npm run test:analytics-ingest` (Node ≥ 22.5; 20 тестов: 17 на чистом ядре и памяти, 3 на локальном SQLite `:memory:`). Результат на момент написания: 20 из 20. Нет вызовов `fetch`, Firebase, Cloudflare. CI не меняется (в CI Node 20, `node:sqlite` недоступен).

## 10. Ограничения
`node:sqlite` экспериментальный; поведение D1 (в т. ч. учёт записей и транзакции Worker) не проверялось; параллельность проверена на однопоточном Node, а не на конкурентных изолятах Workers; нет адаптера D1; нет проверки подписей и rate limit по IP (потребовали бы IP); retention реализован функцией, расписание (cron) не создавалось.
