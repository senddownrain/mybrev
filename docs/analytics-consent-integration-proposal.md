## 1. Что доказано офлайн (P07), а что нет

| Доказано тестами на синтетике, без сети | Не доказано и не утверждается |
|---|---|
| Три замка: build flag ∧ server flag (kill switch) ∧ согласие; по умолчанию все закрыты, любое сочетание кроме ON/ON/согласие обрабатывает 0 пакетов | Что экран согласия юридически достаточен (текст, оператор, срок, язык: `[ЮРИДИЧЕСКАЯ ПРОВЕРКА]`) |

| Те же сценарии (`tests/fixtures/analytics-consent-scenarios.json`) зелёные на WEB и во Flutter | Физические устройства |

## 2. Поведение клиента

```
         build flag OFF ──────────────► модуль отсутствует/мёртв: хранилище не трогается
                │ ON
         server flag (kill switch) OFF ► offer() = отказ, flush() = 0, очередь стирается
                │ ON
         согласие OFF (по умолчанию) ──► offer() = отказ, очередь не создаётся
                │ ON (только явное действие пользователя)
         offer(пакет за закрытые сутки) → очередь (слияние по дню, ≤64 KiB, ≤14 дней)
         flush() при resume/раз в сутки → каждый закрытый день с ≥ 3 ячеек:
                                          1) удалить из очереди и сохранить  2) отправить 3) 204 = sent, иное = lost; повторов нет
```

Стратегия **at-most-once и недосчёт**: сбой после шага 1 теряет пакет; отправка не идемпотентна на сервере, поэтому повтор мог бы завысить счётчики. Мы выбираем занижение и считаем его: `stats.lost` (локально, не отправляется), в отчётах суммы всегда «нижняя оценка» (`totalsAreLowerBounds`). Если удаление из очереди не удалось записать, пакет **не** отправляется. Отправка, начатая до `revoke`, отозвана быть не может (она уже ушла); следующая не стартует. Это должно быть сказано пользователю в тексте отзыва.

## 3. Согласие: правила

- Нейтральные равнозначные кнопки без предвыбора, приложение работает одинаково при отказе; вопрос не блокирует чтение; повторное напоминание не чаще, чем решит владелец (по умолчанию не напоминать).
- Хранение: **только на устройстве** (localStorage / Hive), одно булево значение. **Не** хранить в удалённом профиле, Firestore, аккаунте, cookie третьих сторон, Sentry. Никакого `consent_id`, времени согласия на сервере, версии текста с привязкой к человеку. Если закон потребует доказательство согласия, это отдельное решение с юристом (оно противоречит принципу «ничего не знаем о человеке» и требует нового анализа).
- Любое значение кроме литерала `true` = нет согласия (проверено).
- Пример текста для экрана: черновик B из `analytics-policy-draft.md` (Draft #158), RU/BE/EN, с метками `[ЮРИДИЧЕСКАЯ ПРОВЕРКА]`. **Не использовать в реальной сборке до утверждения.** В закрытом демо P07 стоит баннер `TEST ONLY / NO DATA SENT` и пометка, что флажок не является юридическим согласием.

## 4. Отзыв и удаление (opt-out & deletion)

1. Клиент: `revoke()` = записать `false`, удалить очередь, очистить буфер сборщика (`onPurge`), прекратить `offer/flush`.
2. Уже отправленные агрегаты **нельзя** удалить по запросу человека: сервер не хранит идентификаторов и не может найти «его» ячейки. Это следует честно написать в тексте согласия (и это ограничивает основания обработки, вопрос юристу).
3. Серверное удаление возможно только по сроку хранения (retention, P06 `cleanup`) и аварийно целиком (kill switch + purge таблицы).
4. Данные о факте отзыва на сервер не отправляются.

## 5. Миграция данных

- Локальный тестовый буфер `analytics_local_v1` (WEB localStorage / Flutter Hive) и очередь отправки `analytics_mock_queue_v1` разные ключи. Реальная версия не должна автоматически отправлять накопленное в тестовых сборках до согласия: при первом включении старый буфер либо стирается, либо показывается пользователю как «что будет отправлено» (решение владельца).
- Смена `schema_version` = v3 только через двусторонние тесты (см. контракт); клиент старой версии, получив 426, прекращает отправку и не повторяет.
- Откат: build flag OFF в следующем релизе + kill switch; локальные данные удаляются при первом запуске с `consent=false` (достаточно `purge()`).

## 6. Удалённая конфигурация (kill switch): модель безопасности

- Назначение: **только выключение**. Удалённо нельзя ни включить сбор, ни обойти согласие, ни сменить адрес отправки. Включение возможно лишь релизом с build flag + явным согласием пользователя.
- Значение по умолчанию при любой ошибке/таймауте/отсутствии конфига = **OFF** (fail closed). Конфиг не содержит секретов и не персонален (один и тот же для всех, без заголовков, идентифицирующих клиента).
- Получение конфига не должно само быть аналитическим запросом: подписанный статический файл/значение, кэшируемое на CDN, без параметров запроса. Подпись/целостность (не принимать конфиг по небезопасному каналу) — решение безопасности перед запуском.
- Адрес отправки зашит в сборку; он **не** задаётся удалённо (защита от перенаправления данных).
- Сервер независимо проверяет свой флаг до разбора тела (P06): рассинхронизация клиента и сервера безопасна, пакет получает 503 и считается недосчётом.
