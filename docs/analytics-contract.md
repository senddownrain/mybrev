# Контракт аналитики v2 (WEB + Flutter)

Статус: **контракт, `schema_version = 2`** (изменения относительно v1 — §16). Сетевая
передача выключена. Код контракта (`src/utils/analytics/contract.js`) — только валидатор и функции
бакетов, он не подключён ни к одному экрану. Сетевая передача выключена и не разрешена
(`docs/analytics-privacy.md`). Название продукта «Літургія гадзінаў» не меняется.

Локальный счётчик (без сети; подключён только через флаг сборки `VITE_ANALYTICS_LOCAL=true` для тестовых сборок, решение D-10 = B; в обычной сборке код и данные отсутствуют в бандле, проверено сборкой):
`src/utils/analytics/collector.js`, тесты `tests/analytics-collector.test.mjs`. Он реализует §5-§8
как конечный автомат с внешними часами; Flutter реализует ту же логику и проверяется теми же
сценариями. Маршруты → `section`/`content_id`: `src/utils/analytics/routeMapper.js`; `feature_use` подключён для 24 из 27 id (§16.1: непокрытые — `search_submit`, `offline_update_apply`, `install_prompt_open`, у всех нет однозначного успешного действия в UI). Данные хранятся по §16.2 (буфер `localStorage` только в тестовой сборке; чтение — `window.__analyticsLocal.snapshot()`). Готовность текста и прокрутка (**v2, `src/utils/analytics/readerSignal.js`**): текст материала — блок читалки (`.prayer-reading-surface`, `.readings-content`, `.liturgical-hour-column`, `.bible-reader`, `.compendium-part-outline`); он готов, когда существует, не содержит загрузчика/ошибки (idle-полоса `.v-card__loader` не считается) и в нём есть видимый текст, **без порога в 200 символов** (короткая молитва считается); «не найдено», ошибка и загрузка блока не создают, визит отбрасывается через ≈ 9,5 с. Глубина `sd` — доля именно этого блока, достигшая нижней границы видимой области окна или ближайшего прокручиваемого предка; навигация, подвал и отступы оболочки не учитываются. Слушатель прокрутки пассивный, в фазе capture, чтение геометрии одного элемента на таймере 200 мс; `ResizeObserver` одного блока пересчитывает при смене шрифта/размера; блок недоступен для измерения → `scroll_unmeasurable`. Первый маршрут страницы (прямая ссылка, перезагрузка) учитывается через `router.isReady()`. Проверено на реальных экранах: `npm run analytics:smoke` (эмулятор, не production).

Источник правды для кода: `src/utils/analytics/contract.js`; эталонные векторы для Flutter:
`tests/fixtures/analytics-contract-v2.json`; тесты: `tests/analytics-contract.test.mjs`.
Любое расхождение между этим текстом и кодом — ошибка этого текста.

## 1. Что измеряем и чего не измеряем

Цель — продуктовая статистика публичных разделов. Это не CRM: нет профилей, пользовательских
путей, напоминаний, таргетинга, привязки к пожертвованиям. **Счётчик событий не равен числу людей**:
контракт не содержит никакого способа посчитать уникальных пользователей, и отчёты обязаны
подписываться «открытий», а не «пользователей».

Не измеряются никогда: админка (`/admin/*`), вход (`/login`), всё закрытое для священников
(коллекции `priestProtectedPrayers`, `priestProtectedCategories`, настройки доступа, любые молитвы
и категории с эффективным `priestOnly`), личные молитвы («Мае»/`/my`, `prayer/add`, `prayer/edit`),
заметки, поисковые строки, избранное как список, пожертвования, содержимое текстов.

## 2. Единые значения

| Поле | Значения | Примечание |
|---|---|---|
| `schema_version` | `2` | целое; менять только решением владельца |
| `platform` | `web` \| `android` \| `ios` | Telegram WebApp и PWA — это `web` |
| `app_version` | `^\d{1,2}\.\d{1,2}$` | укрупнённо: major.minor (`4.5.2` → `4.5`); build не отправляется |
| `region` | `BY` \| `OTHER` \| `UNKNOWN` | см. §9; по умолчанию `UNKNOWN` |
| `day` | `YYYY-MM-DD`, UTC | граница локального дня не нужна; сутки по UTC |
| `section` | `today, hours, readings, ordo, prayers, mass, songs, compendium, bible, picker, settings, about` | соответствие маршрутам — §3 |
| `content_id` | `<kind>:<id>`, §4 | только публичные материалы |
| `feature_id` | список §6 | не «все клики», а whitelist |

## 3. Разделы и маршруты

| `section` | Web-маршрут (`src/router/index.js`) | Flutter-маршрут (`lib/router`) | `content_id` |
|---|---|---|---|
| `today` | `/`, `/day/:day` | `/hours` (список дня) | нет |
| `hours` | `/day/:day/ora/:id/<hour>` | `/ora/:date/:dayId/:type` | `hour:<hour>` |
| `readings` | `/readings`, `/readings/:date` | `/readings/...` | `reading:day` (один обобщённый материал: без даты, дня, текста) |
| `ordo` | `/ordo`, `/ordo/:date` | `/hours/ordo` | нет |
| `prayers` | `/prayers*`, `/prayer/:id`, `/p/:id` (кроме Мессы) | `/prayers/*`, `/prayer/:id` | `prayer:<id>` |
| `mass` | `/prayer/<MASS_ORDER_PRAYER_ID>` и варианты Імшы | то же | `mass:order` |
| `songs` | `/songs`, `/song/:id` | `/prayers/songs[/:id]` | `song:<id>` для текста песни |
| `compendium` | `/compendium/*` | `/prayers/compendium/*` | `comp:<docId>` |
| `bible` | `/bible/:language?/:bookId?/:chapter?` | `/bible/:version/:book/:chapter` | `bible:<bel\|ru>:<bookId>` |
| `picker` | `/picker`, `/readings/picker` | `/picker*` | нет |
| `settings` | `/settings` | `/settings` | нет |
| `about` | `/about` | — | нет |

Разделы с видом материала (`prayers`, `mass`, `songs`, `compendium`, `hours`, `bible`) требуют
`content_id`: валидатор отклоняет `screen_view` без него. Поэтому открытие **списка** молитв/песен/глав
как материала не считается `screen_view`: **открытия каталогов считает отдельное событие `catalog_open`**
(`catalog_id` из белого списка §16), поэтому открытие материала и открытие списка никогда не
считаются дважды. Разделы без вида материала (`today, ordo, picker, settings, about`) дают
`screen_view` без `content_id`; `content_id` у них запрещён. «Число открытий» ≠ «число людей».

Идентификатор часа: web `vesper`, Flutter `vespers` — **в контракте всегда `vesper`**, Flutter
преобразует на границе. Девять часов: `invitatorium, morning, lectionis, laudes, terz, sext, non,
vesper, completorium`. Источник: `src/constants/liturgicalHours.js`, `lib/constants/hora_items.dart`.

## 4. Публичные `content_id`

Формат проверяется регулярными выражениями (`CONTENT_ID_PATTERNS`), **принадлежность публичному
инвентарю проверяется отдельно** (`validateContentId(..., { publicIds })`), потому что только
инвентарь исключает закрытое. Инвентарь строится из опубликованной публичной выборки, не из
сырого снимка.

| kind | Формат | Источник | Размер (снимок 2026-10-06) | Пояснение |
|---|---|---|---|---|
| `prayer` | `prayer:` + ID документа: авто-ID Firestore (20 симв.) или slug (`import-*`, `mybrev-*`, `catholicby-yearcycle-NNNNNN`, `order-of-mass-en`) | `prayers` (публичная коллекция) | 115 в бандле 2026-10-13 | инвентарь, см. §4.1 |
| `mass` | `mass:order` | `src/data/mass/order-of-mass.ritual.json` (`primaryPrayerId` = `eMmCtxwyJ75ogmL5rwye`) | 1 | языковые варианты — через `feature_use mass_language_change`, не новым `content_id` |
| `song` | `song:holysongs-` + 20 hex | `songs` | 447 в бандле | |
| `comp` | `comp:` + `[a-z0-9-]` (`p1-s1-ch1`) | `compendium` (документы глав) | 27 в бандле | вопросы Катехизиса схлопываются к главе; число вопросов (~598) не вводится |
| `hour` | `hour:<hour>` | `LITURGICAL_HOURS` | 9 | дата дня и литургическое время не входят в `content_id` |
| `bible` | `bible:<bel\|ru>:<bookId>` | `src/constants/bible.js` (`BIBLE_BOOKS`) = `bible_seed_*.json.gz` Flutter | 73 + 73; идентификаторы веба и Flutter совпадают (сверено) | глава не входит (иначе ~2 500 значений) |

Не входят в `content_id`: идентификаторы дней (`days`, 735), чтений (`readings`, 815), шаблонов,
Ordo-знаменательных дат, заметок Ordo. Они достаточно описаны полем `day` (UTC дата открытия) и
`section`, а высокая кардинальность по датам раскрывала бы редкие практики.

### 4.1 Инвентарь публичных `content_id` (закрыт для кода, ждёт подтверждения владельца)

Инвентарь — файл `src/utils/analytics/public-inventory.json` (750 значений в v2 — раньше 745: prayer 115, song 447,
comp 27, mass 1, hour 9, bible 146), собран `scripts/analytics/build-public-inventory.mjs
--bundle <dir>` из **опубликованного бандла контента приложения** (`assets/content`, версия
`1791877294111`, 2026-10-13), а не из сырого снимка Firestore и без живых чтений. В список попадает
только документ, который бандл публикует и у которого нет `priestOnly` / `effectivePriestOnly`
(в бандле закрытых документов 0; закрытые молитвы физически лежат в `priestProtectedPrayers`,
которая в бандл не попадает). Проверка актуальности: `--check`; тест `analytics-inventory.test.mjs`.

Что известно и что нет:
- Старый снимок `firestore-snapshot-static` (2026-10-06) для инвентаря **непригоден**: 85 его молитв
  совпадают с бандлом, 32 есть только в снимке (без полей `categoryId`/`priestOnly`; среди них 21
  закрытая по `docs/priest-access.md`), 30 есть только в бандле (появились позже). Это объясняет
  прежнее расхождение «96 против 85»: оно было артефактом старой схемы снимка.
- Бандл — это публикация приложения; то, что публичная коллекция `prayers` в production в точности
  равна бандлу, **не проверено живым чтением** (`НЕ ПОДТВЕРЖДЕНО`, квота/разрешение). Для Flutter
  бандл и есть то, что видит пользователь; для веба возможны молитвы, добавленные в админке после
  публикации бандла: они **не измеряются** (fail closed) до пересборки инвентаря.
- 26 молитв `catholicby-yearcycle-*` и ряд `import-*` попали в публичную коллекцию через импорт
  (`docs/priest-access.md`: скрипт импорта «незавершённый»). Включены, потому что опубликованы;
  владельцу нужно подтвердить, что их публичность намеренна — если нет, убрать из публикации и
  пересобрать инвентарь.
- Правило безопасности по умолчанию — fail closed: неизвестный `content_id` не измеряется. Инвентарь
  поставляется с клиентом (веб и Flutter) и копией на сервере; формат ID в `contract.js` — только
  проверка формы, принадлежность инвентарю проверяется отдельно.

## 5. События (единственные пять)

Единицей передачи является **агрегированная ячейка** (`cells[]`), а не поток событий: клиент
считает в памяти и сбрасывает суммы. Поля ячейки строго по whitelist; любое лишнее поле — отказ.

| `e` | Поля | Когда увеличивается `n` |
|---|---|---|
| `screen_view` | `section`, `content_id?`, `n` | новый «визит» экрана (§7), у которого есть `content_id` или раздел без списков |
| `text_read` | `section`, `content_id`, `metric` (`fv`\|`er`\|`sd`), `bucket`, `n` | конец визита с `content_id`, ≥1 с на переднем плане |
| `catalog_open` | `catalog_id`, `n` | визит ≥ 1 с на каталоге/списке из §16 (без `section`, без текста) |
| `feature_use` | `feature_id`, `section`, `n` | действие пользователя, выполненное успешно; не при каждом tap/scroll |
| `measurement_error` | `error_id`, `n` | сбой измерения (§8) |

Три метрики текста **не склеиваются в одну** и отправляются как три независимые гистограммы
(маргиналы). Совместное распределение (время × глубина × оценка) не передаётся: это снижает
кардинальность (≤ 6+6+6 ячеек на материал вместо 216) и уменьшает риск раскрытия поведения
одного устройства. Доля коротких открытий считается как `fv=lt5s` / все `fv`.

### 5.1 Три метрики

1. **`foreground_visible_time`** (`metric=fv`). Время, пока экран с текстом виден и приложение на
   переднем плане. Паузится на `visibilitychange=hidden` / `AppLifecycleState.paused|inactive`.
   Не обрезается по бездействию; неподвижность не означает, что человек не читает или не молится.
   Максимум на визит — 1800 с (`MAX_VISIT_SECONDS`), остальное отбрасывается.
2. **`estimated_reading_time`** (`metric=er`). Грубая оценка сверху:
   `er = min(fv, reachedChars / (6 · 120) · 60)`, где `reachedChars = totalChars · max_scroll_fraction`
   (для текста без прокрутки — `totalChars`). Константы `CHARS_PER_WORD = 6`,
   `READING_WORDS_PER_MINUTE = 120` — **допущение, не калибровка**: скорость молитвенного чтения
   вслух/про себя не измерена на белорусских текстах (`НЕ ПОДТВЕРЖДЕНО`). Оценка не доказывает
   чтения и обязана сопровождаться этой оговоркой в любом отчёте. Не пишется для коротких открытий.
3. **`max_scroll_depth_bucket`** (`metric=sd`). Максимальное положение нижней границы окна просмотра
   относительно прокручиваемой высоты: `fit` (текст помещается без прокрутки), `p0_25`, `p25_50`,
   `p50_75`, `p75_99`, `p100` (≥ 0,98). Достижение низа не означает завершение чтения.

Посекундных треков, временных меток событий и последовательностей экранов нет.

### 5.2 Бакеты

| Метрика | Бакеты (границы в секундах, нижняя включительно) |
|---|---|
| `fv`, `er` | `lt5s` <5 · `5_15s` · `15_60s` · `60_180s` · `180_600s` · `gte600s` ≥600 |
| `sd` | `fit` · `p0_25` · `p25_50` · `p50_75` · `p75_99` · `p100` |

Эталонные входы/выходы — в `tests/fixtures/analytics-contract-v2.json` (поле
`visibleSecondsBuckets`, `scrollBuckets`, `readingEstimates`). Граница округления: время не
округляется заранее, бакет берётся от точного значения (4,99 → `lt5s`, 5 → `5_15s`).

## 6. `feature_id` (whitelist, 27)

`text_scale_change, text_settings_open, theme_change, font_family_change, keep_screen_on_toggle,
favorite_add, favorite_remove, share_use, copy_use, search_open, search_submit, date_pick,
picker_open, hour_switch, hour_option_select, psalmody_layout_change, chords_toggle,
chord_transpose, chord_layout_change, mass_language_change, mass_section_nav,
ordo_diocese_change, bible_language_change, bible_chapter_nav, back_to_top,
offline_update_apply, install_prompt_open`.

Правила: значение настройки (размер, тема, язык) **не передаётся** (v1 и v2) — только факт использования
(иначе комбинации раскрывают конфигурацию устройства); `search_submit` не содержит запроса;
`share_use`/`copy_use` не содержат что делились и куда; `favorite_*` не содержит какая молитва.
Оценка кардинальности: 27 × 12 разделов ≤ 324 ячейки на день и платформу, реально ≈ 60. Новая кнопка
= новая версия контракта (добавление значения — `schema_version` не меняется, но требует обновления
веб-, Flutter- и серверного allowlist одновременно).

`install_prompt_open` — только web; `offline_update_apply` — только Flutter/PWA update.

## 7. Что считается визитом (счёт при возврате по навигации)

Визит = непрерывное присутствие на паре (`section`, `content_id`) на переднем плане.

- Новый визит: переход на материал; возврат на материал кнопкой «назад»/«вперёд» (bfcache,
  `popstate`) — **это новый визит**.
- Не новый визит: смена только `?lang`/`#hash`/`?q`, переключение языка Імшы, прокрутка к секции;
  возврат на передний план менее чем через 5 минут в фоне (фон не входит в `fv`).
- Фон ≥ 5 минут закрывает визит; возвращение открывает новый.
- Двойное срабатывание на один и тот же материал в пределах 2 с — один визит.
- Визит короче 1 с (`MIN_COUNTED_VISIT_SECONDS`, редиректы, например Імша → вариант) отбрасывается
  без записи. Визит 1–5 с — «короткое открытие»: `screen_view` и `text_read fv=lt5s`, без `er`/`sd`.
- Закрытие вкладки/выход: запись визита в локальный буфер при `pagehide`/`visibilitychange=hidden`;
  без синхронных запросов, `sendBeacon` не используется в v1 и v2.
- Один и тот же человек, открывший материал дважды, даёт два визита; контракт не отличает его от
  двух людей.

## 8. Ошибки измерения (`measurement_error`)

`clock_anomaly` (отрицательная/скачкообразная дельта времени), `storage_unavailable` (нет
localStorage/Hive), `queue_overflow` (локальный лимит достигнут, данные отброшены),
`visibility_unsupported`, `scroll_unmeasurable`. Без текста ошибки, стека и URL. Ошибки приложения
остаются в Sentry/логах и не входят в аналитический контракт.

## 9. Регион

`BY | OTHER | UNKNOWN`, по умолчанию `UNKNOWN`. Допустимые способы определения (решение владельца,
`D-04` в `docs/analytics-privacy.md`; ни один не включён): (a) локальная эвристика без сети — часовой
пояс `Europe/Minsk` и/или локаль `be-BY`; VPN/роуминг/путешествия искажают оценку, это приблизительный
сигнал, не юридический факт местонахождения; (b) страна от граничной сети принимающего сервера
(Cloudflare `request.cf.country`), сразу сводимая к трём значениям и не записываемая. GPS, точное
местоположение, IP в аналитическом хранилище запрещены. «OTHER» не означает одну правовую зону:
правила для ЕС/EEA/UK/США не сведены, поэтому до решения владельца `OTHER` и `UNKNOWN` — только
локальный режим.

```json

```

В пакете нет: идентификатора пользователя/устройства/установки/сессии, меток времени (только
`day`), счётчика последовательности, версии ОС, модели, языка, URL, referrer, поисковых строк. Один
пакет — одни сутки. Ограничения: ≤ 200 ячеек, ≤ 16 КиБ, `n` 1…10 000, ячейки уникальны (счётчики
сливаются на клиенте). Валидатор `validatePacket` — единый для веба, сервера и (по эталонным
векторам) Flutter. Ответы сервера: `204` принято или молча отброшено при лимите (клиент не повторяет),
`400` невалидно (клиент удаляет пакет), `410` kill switch (клиент останавливает отправку, §12),
`429/5xx` — повтор с экспоненциальной паузой, пакет удаляется через 14 дней.

**Локально ≠ анонимно после отправки.** Пакет одного устройства за один день, пришедший с IP,
остаётся потенциально идентифицируемым (редкая комбинация материалов + IP + момент). Поэтому формат
минимизирован, но **не объявляется анонимным**: правовой статус — `НЕ ПОДТВЕРЖДЕНО`, отправка
запрещена до решений владельца (`docs/analytics-privacy.md`).

## 11. Хранение итогов (сервер, если когда-либо будет включён)

Только допустимые агрегаты; запись — upsert-инкремент, без сырых пакетов и без IP:

```text
agg_cells(
  day TEXT, schema INTEGER, platform TEXT, app_version TEXT, region TEXT,
  e TEXT, section TEXT, content_id TEXT, feature_id TEXT, error_id TEXT,
  metric TEXT, bucket TEXT,
  n INTEGER,
  PRIMARY KEY (day, schema, platform, app_version, region, e, section, content_id,
               feature_id, error_id, metric, bucket))
```

(отсутствующие значения хранятся как пустая строка, чтобы ключ был детерминирован). Из этих
строк без переинструментирования строятся отчёты: по дням, по версии (укрупнённо), по платформе,
по разделу, по материалу, по кнопке, по распределению времени/глубины. Интерфейс отчётов не
проектировался. Подавление малых групп: отчёт показывает ячейку, только если суммарный `n` за
выбранный период ≥ 10; остальное сводится в «прочее» (правило отчётов, не гарантия анонимности
единичных пакетов).

Срок хранения агрегатов (предложение, `D-06`): 395 суток; на устройстве несентые дни — 14 суток
(`LIMITS.maxLocalDays`). Удаление: по сроку — задачей очистки; по запросу конкретного человека —
**невозможно** (в данных нет ключа, по которому его строки можно найти); это следствие дизайна и
оно же аргумент, что данные не персональные, — аргумент `НЕ ПОДТВЕРЖДЁН` юристом.

## 12. Сетевой шлюз и kill switch

```text
analytics_network_enabled = false        (по умолчанию, во всех сборках, на всех платформах)
```

Отправка возможна **только если одновременно истинно всё**:

1. Сборочный флаг `ANALYTICS_NETWORK_ALLOWED` (константа `ANALYTICS_NETWORK_DEFAULT` в коде;
   по умолчанию `false`; включается только релизом после закрытия privacy gate).
2. Удалённый конфиг (статический JSON на Hosting, без сервера, **не** Firebase Remote Config —
   он требует installation ID) содержит `analytics_network_enabled: true`. Нет файла, ошибка
   загрузки, невалидный JSON → считать `false` (fail closed). Конфиг может только выключить, не
   включить то, что выключено сборкой.
3. Для платформы/региона выполнено условие из матрицы `docs/analytics-privacy.md` (согласие и т.д.).
4. Пользователь не отключил статистику в настройках.

Выключение немедленно: очищает сетевую очередь, останавливает таймеры, не отправляет ничего
дополнительно. Kill switch: любой из: конфиг `false`; ответ сервера `410`; `min_app_version`
выше текущей. После `410` отправка не возобновляется без нового конфига `true` и новой версии.
Локальный счёт при выключенной сети может идти (если локальный режим разрешён) и не создаёт
сетевых запросов.

Очередь: ≤ 7 закрытых суток и ≤ 64 КиБ в хранилище; ≤ 1 запрос за 6 часов; не в момент взаимодействия
(`requestIdleCallback` / после `AppLifecycleState.resumed` с задержкой); таймаут 5 с; провал не
влияет на чтение; переполнение отбрасывает самые старые сутки и увеличивает `queue_overflow`.

## 13. Правила кардинальности и минимизации

- Максимум значений: `content_id` ≈ 96 + 1 + 447 + 27 + 9 + книги Библии (`НЕ ПОДТВЕРЖДЕНО`) ≈ до 650;
  метрик на материал ≤ 18 ячеек. Реальные суточные пакеты содержат лишь открытые материалы.
- Не вводить: время суток, число часов подряд, цепочки «материал → материал», комбинации
  «материал × настройка», значения настроек, длительности в секундах, число вопросов Катехизиса.
- Любое новое поле — только через новую версию контракта, обновление валидатора, сервера, Flutter
  и `docs/analytics-privacy.md`.

## 14. Совместимость и версии

`schema_version` — формат пакета и словари; новые значения whitelist без смены формата — минорное
изменение документа, но обязательно одновременно в вебе, Flutter и сервере (иначе сервер отклонит
пакет). Версия API — в пути (`/v1/…`). Сервер обязан принимать предыдущую `schema_version` минимум
90 суток после выхода новой. Клиент, получивший `400`, удаляет пакет и не повторяет.

## 15. Что готово к будущим графикам (без интерфейса)

Источники `agg_cells` достаточны для: открытий по дням/версиям/платформам/разделам/материалам;
распределения `fv`/`er`/`sd` и доли коротких открытий; использования кнопок; сравнения «до/после»
релиза через `app_version`. Ограничения: нельзя получить уникальных пользователей, возвраты
пользователя, воронки, когорты, удержание, совместные распределения.

## 16. Изменения v1 → v2 и миграция

| Что | v1 | v2 |
|---|---|---|
| `schema_version` | `1` | `2`; сервер и клиенты принимают только `2` (данных v1 нигде нет: сеть не включалась) |
| Ежедневные чтения | `readings` без `content_id`, `text_read` невозможен | `content_id = reading:day` обязателен; доступны `screen_view`, `fv`, `sd`, `er`. Даты, ID дня, текст не передаются; различение «чтение / псалом / Евангелие» **не вводится** (одна страница, одно значение) |
| Каталоги | не считались | событие `catalog_open`: `hours_list, prayers_home, prayers_all, favorites, songs, bible_books, compendium_home` |
| Компендиум | `comp:<глава>` | единица чтения — **часть** `comp:p1…p4` (глава — якорь внутри части); главы `comp:p1-s1-ch1` остаются допустимыми (старый маршрут `node/:id`) |
| Инвентарь | 745 ID | 750 ID (+`reading:day`, +4 части компендиума) |
| Фикстура | `analytics-contract-v1.json` | `analytics-contract-v2.json` |

Различение Евангелия — предложение, не реализовано: потребовало бы `IntersectionObserver` по
блокам страницы и значения `reading:gospel`; повышает детализацию, поэтому нужно решение владельца.

### 16.1 Статус инструментации `feature_use` (веб)

Подключено на реальных успешных действиях (литерал в вызове `trackFeature('…')`, без значений):
`text_scale_change, font_family_change, theme_change, keep_screen_on_toggle, ordo_diocese_change,
favorite_add, favorite_remove, psalmody_layout_change, chords_toggle, chord_layout_change,
chord_transpose, text_settings_open, picker_open, date_pick, back_to_top, copy_use, share_use,
mass_language_change, mass_section_nav, bible_chapter_nav, bible_language_change, search_open,
hour_switch, hour_option_select` (24 из 27). Три последних добавлены при закрытии PR #129 и проверены в реальном UI
(`npm run analytics:smoke`): `search_open` — открытие панели поиска Библии (текст запроса не передаётся),
`hour_switch` — выбор другой гадзіны в меню (текущая не считается), `hour_option_select` — выбор варианта гадзіны
(`v-select` инвітаторыя и переключатель законных вариантов дня; значение не передаётся).
**Не подключены, с обоснованием:**

| id | Статус | Почему |
|---|---|---|
| `search_submit` | NOT APPLICABLE | в UI нет явной отправки: поиск работает по набору с задержкой (debounce); счёт по вводу считал бы набор, а не использование, и приблизился бы к тексту запроса |
| `offline_update_apply` | NOT APPLICABLE | в коде нет UI применения обновления PWA (`registerSW`/`onNeedRefresh` отсутствуют, автообновление без действия пользователя) |
| `install_prompt_open` | NOT APPLICABLE | в коде нет обработчика `beforeinstallprompt` и кнопки установки |

Поиск у молитв и песен (`search_open`) не подключён: это строка ввода на странице, а не отдельное действие. Новых
элементов интерфейса ради аналитики не добавлялось.
`chord_transpose` не считает возврат к нулю. Событие относится к текущему экрану (`section`);
на экранах без раздела (админка, вход) оно отбрасывается.

### 16.2 Хранение тестовых данных (решение противоречия)

Раньше документы говорили «`localStorage` для счётчиков» и «только в памяти». Принято: **в тестовой
сборке** (`VITE_ANALYTICS_LOCAL=true`) один небольшой буфер агрегатов в `localStorage`
(`analytics_local_v1`): запись только при `visibilitychange=hidden`/`pagehide` (не на scroll/tap),
≤ 64 КиБ (старейшие дни отбрасываются, `queue_overflow`), срок 14 суток, без идентификаторов, очистка
`window.__analyticsLocal.clear()`. В обычной сборке хранилище не используется.
