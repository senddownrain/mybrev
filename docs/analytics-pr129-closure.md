## 1. Что исправлено

### B1. Готовность читалки (короткие молитвы, реальный контент)
Было: порог `MIN_TEXT_CHARS = 200`, текст бралcя из всего `.v-main` (включая навигацию), 4 опроса по 1,5 с.
Стало (`src/utils/analytics/readerSignal.js`, `localAnalytics.js`):
- у каждого раздела свой **блок читалки** (классы реальных экранов: `.prayer-reading-surface`, `.readings-content`, `.liturgical-hour-column`, `.bible-reader`, `.compendium-part-outline`); они рендерятся видами только после загрузки данных. Загрузка, ошибка и «не найдено» блока не создают;
- готов = блок есть, внутри нет загрузчика/ошибки (пустая полоса `.v-card__loader` каждой карточки Vuetify **не** считается) и есть видимый текст (`innerText`), без порога по длине: короткая молитва считается;
- `er` считается по длине именно этого блока, а не всей страницы;
- токен маршрута отменяет отложенные проверки при быстром переключении и Back; блок, пересобранный видом во время загрузки (как у часов), подхватывается заново;
- первый маршрут страницы (прямая ссылка, перезагрузка) раньше **терялся**, потому что модуль подгружается лениво после первой навигации; исправлено через `router.isReady()` — это найдено только проверкой на реальных экранах;
- ожидание готовности ограничено ≈ 9,5 с, затем визит отбрасывается (`discardView`).
Ограничение: время `fv` считается с входа на маршрут, включая загрузку (визит отбрасывается, если материал так и не появился); текст внутри свёрнутых блоков не учитывается, если браузер сообщает об этом через `innerText`.

### B2. Область прокрутки
Было: `window.scrollY`, `innerHeight`, `documentElement.scrollHeight` целого документа.
Стало: приложение скроллится окном (во всех видах чтения нет собственных прокручиваемых контейнеров; проверено `getComputedStyle` предков на чтениях и часах), глубина `sd` — доля **блока читалки**, достигшая нижней границы видимой области окна или ближайшего прокручиваемого предка (если он есть); `fit` = блок виден целиком с верха страницы. Навигация, подвал и отступы оболочки не входят. Слушатель пассивный, capture, чтение геометрии двух элементов на таймере 200 мс (без обхода дерева, I/O и реактивных обновлений); `ResizeObserver` на одном блоке пересчитывает при смене шрифта/ресайзе/поздней загрузке; блок без размеров → `scroll_unmeasurable` (после второй попытки), глубина не выдумывается.

### Функции `feature_use`: 24 из 27
Добавлены `search_open` (панель поиска Библии), `hour_switch` (меню гадзін, текущая не считается), `hour_option_select` (выбор варианта инвітаторыя и варианта дня). Оставшиеся: `search_submit`, `offline_update_apply`, `install_prompt_open` — **NOT APPLICABLE** (нет явной отправки поиска; в коде нет UI обновления PWA и установки), с обоснованием в `analytics-contract.md` §16.1. Новых элементов UI не добавлено; значения не передаются.

## 6. Sentry (анализ, без изменений)

`src/plugins/sentry.js`: работает только при `PROD` и заданном `VITE_SENTRY_DSN` (задан ли он в production — не проверялось); `tracesSampleRate 0.1`, `replaysSessionSampleRate 0.1`, `replaysOnErrorSampleRate 1.0`, `browserTracingIntegration({ router })`. Риск: транзакции с реальными путями (`/prayer/<id>`, `/song/…`, `/bible/…`) и replay DOM — это более подробная телеметрия, чем контракт аналитики, с IP транспорта; текст в replay маскируется настройками по умолчанию, это не отключалось и не проверялось. Варианты (решение D-08 владельца): (a) replay и tracing = 0; (b) оставить ошибки и параметризовать пути в `beforeSend`/`beforeBreadcrumb`; (c) отключить. Рекомендация (b) + replay = 0.
