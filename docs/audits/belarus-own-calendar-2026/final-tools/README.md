# Воспроизведение заключительного аудита

Эти утилиты не исправляют календарь и не содержат Firestore write RPC. Анализ использует приватный локальный snapshot через штатный `scripts/lib/firestore-snapshot.mjs`. Полный snapshot намеренно не включён в Git: по одним опубликованным хешам нельзя восстановить содержимое БД или независимо повторить сравнение без исходных данных.

Нужны зависимости Web (`npm ci`), Node с поддержкой проекта и Python 3. В командах ниже `AUDIT_REPO` — абсолютный путь к репозиторию, `AUDIT_WORK` — отдельная приватная рабочая папка. Под ней должен находиться `private/manifest.json` с календарным snapshot этой фазы. Рабочую папку следует держать вне репозитория, с правами 0700. Не выводите её содержимое в публичный журнал.

Последовательность локального анализа, без сетевых чтений Firestore:

```bash
node "$AUDIT_REPO/docs/audits/belarus-own-calendar-2026/final-tools/compare-production.mjs" --repo "$AUDIT_REPO" --work "$AUDIT_WORK"
node "$AUDIT_REPO/docs/audits/belarus-own-calendar-2026/final-tools/normative-cases.mjs" --repo "$AUDIT_REPO" --work "$AUDIT_WORK"
node "$AUDIT_REPO/docs/audits/belarus-own-calendar-2026/final-tools/probe-cache.mjs" --repo "$AUDIT_REPO" --work "$AUDIT_WORK"
python3 "$AUDIT_REPO/docs/audits/belarus-own-calendar-2026/final-tools/build-final-data.py" --repo "$AUDIT_REPO" --work "$AUDIT_WORK" --out "$AUDIT_WORK/results"
```

Первый скрипт проверяет checksum snapshot, все 316 постоянных документов, 15 годовых документов и три модели по 16 068 сочетаний дат/диоцезий. Он намеренно останавливается, если исходные предпосылки этого аудита изменились. Второй делает 25 нормативных проекций только в памяти. Третий воспроизводит шесть механизмов кэша и два контроля; PASS означает успешное воспроизведение исходного поведения, а не исправленный дефект. Последний строит CSV и безопасные доказательства в новой локальной папке; он не заменяет вручную подготовленные отчёты.

`capture-calendar.py` — отдельный ограниченный REST reader для зафиксированного Web build. Без существующего manifest он требует явного `--live-read`; при существующем manifest возвращается без сети. В этой фазе захват уже выполнен один раз, повторять его для тестов не требуется. Скрипт ограничивает ресурсы, число запросов и размер страниц, не делает retry, не читает тела notes и прекращает работу, если серверная версия notes требует нового плана проверки. Это не универсальная утилита резервного копирования. Новое чтение должно оставаться в явно разрешённых владельцем границах; `--live-read` не является разрешением на запись.

Фактические результаты и ограничения находятся в `../final-evidence/`, `../FIRESTORE_AUDIT.md` и `../FINAL_REPORT.md`. Исходные логи тестов сохранены, включая 10 пропущенных проверок и отсутствие raw-source проверки детерминированной генерации.

Проверка полноты сдачи (тоже без сети):

```bash
python3 "$AUDIT_REPO/docs/audits/belarus-own-calendar-2026/final-tools/verify-artifacts.py" --repo "$AUDIT_REPO"
```

Она сопоставляет все исходные строки с новой таблицей, проверяет 23 дополнительных назначения, 17 рангов, 3 даты, 5 пропусков, 172 решения, 18 разделов отчёта, сохранность хешей первого аудита и ограничение Git diff документацией.
