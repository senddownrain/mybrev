# Подтверждённые варианты источников production

2026-11-17. После merge Web #259 и Flutter #114 штатно опубликованы Firestore rules и Hosting (main 055bf24f7e651450554c029123776986b62adecc, workflow 44080348531). Опубликованная policy v2 подтверждена по no-store marker и фактически отдаваемому JavaScript.

Выполнен один последовательный scoped export: 389 prayers, 43 priestProtectedPrayers, 226 prayerDrafts; дополнительно 22 публичные и 8 защищённых категорий для существующего privacy filter и два документа prayers manifest. Всего 690 возвращённых документов, 9 Firestore REST requests, включая одно discovery и две страницы prayers. Других молитвенных коллекций discovery не обнаружило. Private snapshot и страницы сохранены только в ignored backups; production content/source values и IDs не копируются в публичный отчёт.

Экспорт обнаружил известные полные названия, не покрытые прежними aliases. Этот follow-up добавляет варианты к существующим записям /sources; канонические названия, библиография, notices и роли не меняются.

«Агенда. Сакрамэнталіі» с разными частями не отождествляется автоматически с изданием 2010: это не подтверждено первичным материалом. «Парафіяльная Агенда» Пинск 2018 тоже не подменяется «Літургічнай агендай». Повреждённое название и private-use формулы без подтверждённого источника остаются спорными. Такие исходные значения сохраняются полностью.

Локальный dry-run из того же snapshot: 658 проверено, 432 в опубликованных коллекциях, 226 draft collection records всех статусов; 59 документов со страницами, 612 изменений только source/sourceBook (361 public, 40 protected, 211 draft); 602 длинных атрибуции. Остались 48 спорных документов / 63 поля, включая missing и empty. SHA проверяемого плана: 73a601acbbd75c5ba3858e64a98e53ff3448987f7dba5c96b3f61ae6e4bd9154.

Вначале требуется публикация policy v3 с этими aliases; затем apply того же плана с точными updateTime. Этот документ не утверждает, что production source-only apply уже выполнен. Новый snapshot не нужен.

Уточнение счётчиков: prayerDrafts содержит 110 status=draft, 49 legacy needs_review и 67 уже published draft records; проверены все 226, статусы не меняются. Из 63 старых bundle disputed IDs в текущем полном snapshot обнаружен 51: для 30 текущая явная атрибуция подтверждена, 21 остаётся в отчёте; 12 ID отсутствуют и не воссоздаются. Проверено 54 source/import regression tests, 3 пропущены из-за отсутствующих внешних первичных архивов. Офлайн CLI capture протестирован с подменённым HTTPS transport: страницы/manifest context/timestamp precision/один 429 без retry; реальных Firebase requests в этих тестах 0.
