# Праздничная сборка существующих Common-вариантов WEB

Выбор варианта уже реализован в `assemblyChoices` / `assembledTemplates`:
Proper берётся из `liturgicalProperTexts` (с совместимостью с прежними `days`),
Common — из `liturgicalTemplates`, Feria — из текущего temporal-документа.
`assembleOffice` уже поддерживает приоритет собственных текстов, ссылки
`_fieldRules`, сезонные варианты Common, происхождение полей и диагностику.
Чтение и его респонсорий хранятся вместе в полях `R`, `R1`, `R2`.
Псалмы/песни и антифоны хранятся отдельно: `Ps1…3`, `Ant1…3`.

Изменение ограничено уже доступным выбором Common у воспоминаний:

- Ютрань: Proper, затем Common; псалмы/песнь — из существующего
  `sunday-week-1`, если нет собственных текстов или явного собственного правила.
- Нешпары и Гадзіна чытанняў: Proper, затем выбранный Common.
- Отсутствующий элемент остаётся пустым и попадает в `missing` /
  `_missingFields` и `integrity` / `_integrityErrors`; автоматической
  будничной замены, в том числе первого чтения, нет. Явные структурированные
  правила источника продолжают действовать.
- Собственная молитва и собственное второе чтение сохраняются.
- Te Deum учитывает праздничную сборку выбранного варианта в существующем
  ридере; календарный descriptor и ранг остаются прежними.
- Для расширенного Common-варианта не материализуются первые Нешпары.
  Дневные часы и Комплеторий сохраняют прежнюю сборку.

Вариант «З дня», существующая сборка праздников/торжеств и legacy-документы
не изменены. Новых Common-привязок, переключателей и копий псалмов нет.
Обновлена существующая `CONTENT_REVISION`: сохранённые результаты сборки
должны обновиться при следующей загрузке online; offline-копии сохраняются.

## Универсальное разрешение базы Common

Специальная проверка ID Павла Креста удалена. В `assembleOffice` используется
небольшая `commonBaseRule(proper, templateId)`: она возвращает обычное правило
`{ source: 'template', template: 'holy-men' }` или `holy-women` для уже
существующего resolver. Список из 20 полей удалён из кода: по вводной рубрике
наследуется любое отсутствующее поле трёх основных часов, после собственных
текстов и явных правил выбранного Common. Proper по-прежнему имеет приоритет.

Правило применяется к выбранному Common, включая уже существующую сборку
праздников/торжеств, только в Гадзіне чытанняў, Ютрані и Нешпарах.
Готовые собственные поля не меняются; воскресные псалмы Ютрані разрешаются
отдельно прежним механизмом. Сезон базового Common учитывается тем же
`seasonalTemplateGetter`. Шаблоны и их `_fieldRules` не мутируются.
«З дня», дневные часы, Комплеторий, первые Нешпары, Te Deum и Invitatorium
этим дополнением не меняются.

### Какие структурированные признаки используются

Изначально проверены модель Ordo, локальные `patchs/db-feasts`,
`patchs/db-templates` и snapshot: явного признака пола или базового Common
в них не было. В завершающем этапе `_commonBase` подготовлена локально
для оставшихся случаев на основании источников; в Firestore она пока не внесена.

Используются только уже существующие привязки `_templates`:

| Привязка святого | База для частного Common | Основание |
| --- | --- | --- |
| `holy-men` | `holy-men` | прямая существующая привязка |
| `holy-women` | `holy-women` | прямая существующая привязка |
| `pastors` | `holy-men` | литургическая категория святых в священном сане |
| `virgins` | `holy-women` | литургическая категория святых дев |

Значение категорий берётся из существующего каталога Common, а не из имени
святого, окончания заголовка или молитвы. Common пастырей содержит варианты
папы/епископа/пресвитера; ср. также [канон 1024](https://www.vatican.va/archive/cod-iuris-canonici/eng/documents/cic_lib4-cann998-1165_en.html).
Common дев в белорусском источнике — том III, строки 4123–4130.
Разбор текстов/регулярных выражений для определения пола в runtime отсутствует.

Павел Креста и Бруно разрешаются через существующий `pastors`, Жанна Франсуаза
дэ Шанталь — через `holy-women`, Клара — через `virgins`. Это одни и те же
правила для любых ID; тесты меняют ID и заголовок без изменения результата.

Если структурированные признаки указывают на обе базы, источник не выбирается
(`base-common-ambiguous`). Если признаков нет или привязки помечены
`_templatesInferred`, возвращается `base-common-unconfirmed`.
`doctors-of-church`, мученики, `religious`, `educators`, `works-of-mercy`
сами по себе не определяют мужскую/женскую базу.

### Минимальная явная метаинформация

Для ранее неоднозначных документов подготовлено одно необязательное свойство
существующего Proper, без новых текстов, документов и пользовательских выборов:

```json
{
  "_commonBase": {
    "religious": "holy-men"
  }
}
```

Для законницы значение — `holy-women`; для другого частного Common используется
его ключ. Это одна ссылка, а не копия 20 правил. Явная метаинформация имеет
приоритет над выводом из категорий. Допустимы только базы, разрешённые рубрикой
данного Common; недопустимое значение даёт `base-common-invalid`.
Поддержка чтения метаинформации реализована. Локальные источники и импортные
артефакты обновлены после ручной проверки каждого случая, без анализа имён
в runtime. Опубликованные документы не изменены.

### Семь основателей сервитов

Источник `patchs/feasts/17-02-seven-servite-founders.json` прямо описывает
семерых мужчин; второе чтение, обе евангельские антифоны и молитва коллективные.
`holy-men` — название общего формуляра, а не признак «один святой».
Общие псалмы и антифоны праведника не переписываются во множественное число.
Гимны `religious` и разрешённые общие тексты остаются в печатной редакции;
отдельный профиль одного святого не выбирается и альтернативы Common не
фильтруются к одному субъекту.

Обнаружен конкретный дефект: Proper хранит коллективную молитву под
`laudesPr`/`vesperPr`, но не под `officeOfReadingsPr`. Без ссылки служба чтений
получала бы общую молитву с `N.`. Добавлено небольшое универсальное правило
в уже существующий resolver: при выбранном Common и отсутствии собственной
`officeOfReadingsPr`/явного правила ссылка ведёт на собственную `laudesPr`.
Она разрешается прежней очередью `ref`, без специальной проверки ID.

Текст не копируется. Во всех трёх основных часах Common-варианта используется
существующая молитва о семи братьях. Коллективные антифоны и второе чтение
сохраняют приоритет Proper. Это исправление намеренно не меняет прежнюю
ветку «З дня»: её подбор молитвы службы чтений оставлен как до PR, согласно
ограничению текущей задачи. Отдельных профилей одного/нескольких святых не
создано; собственные и печатные общие тексты не переписывались.

### Сохранение метаданных при генерации и импорте

Ранее `_commonBase` читалась runtime, но `buildSparseOutput` отбрасывала
произвольные служебные свойства источника. Добавлен перенос только этого
свойства. Метаданные заданы в 22 исходных файлах; три диоцезных варианта
Станислава получаются из одного источника. Scaffold Цэліны в Витебске берёт
только метаданные того же `_celebrationId` из источника Гродно, без её Proper.
Конфликтующие метаданные разных источников останавливают генерацию.
Два случая без собственного источника используют `commonBase` в существующих
решениях scaffold. Подтверждение базы не меняет `_templatesInferred` и
не объявляет подтверждёнными прежние автоматически полученные UI-привязки.
Структурное сравнение с предыдущим commit подтвердило: в 22 исходных и
27 generated JSON изменена исключительно `_commonBase`; все тексты,
ранги, диоцезы и существующие правила совпадают побайтно на уровне значений.

Обычный `documentOf` / `buildFeastTargets` импортера уже сохраняет все свойства
сгенерированного документа, поэтому переписывать его не потребовалось.
Выполнена воспроизводимая локальная генерация:

```powershell
npm run generate:fixed-feasts -- --offline
```

Новый `--offline` запрещает обращаться к Firestore при отсутствии локальных
кешей. Изменены только 27 целевых generated-документов: 29 значений
