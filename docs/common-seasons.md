# Сезонныя варыянты агульных тэкстаў (Commons)

Агульныя тэксты (`liturgicalTemplates`, `_kind: 'common'`) у трох тамах Літургіі
гадзінаў маюць сезонныя адрозненні: Адвэнт / Нараджэнне Пана (том I), Вялікі
пост / Велікодны перыяд (том II); том III — Звычайны перыяд (базавы тэкст).

## Мадэль

Ідэнтыфікатар Common і яго плоскія базавыя палі (`vesper1Ant3`,
`officeOfReadingsR1`, `laudesPr`, …) **не мяняюцца** — гэта тэкст Звычайнага
перыяду (том III). Да іх дадаецца разрэджаны аб'ект дэльт:

```json
"_seasonalVariants": {
  "lent":   { "vesper1Ant3": "<p>…</p>", "vesper1Ps3": "<p>…</p>" },
  "easter": { "vesper1Ant3": "<p>…</p>" }
}
```

* Сезоны: `advent`, `christmas`, `lent`, `easter`. `ordinary` — гэта плоскі базавы тэкст і не дублюецца.
* Поле няма ў дэльце → **спадкуецца база** (няма override). Значэнне: радок або масіў радкоў → замена тэксту;
  `null` → у гэты сезон поле **наўмысна пустое** (`_fieldRules[field] = { omit: true }`);
  `{ "rule": { … } }` → структураванае правіла `_fieldRules` замест тэксту (напр. `{ "ref": "vesperHymn" }`).
* Нічога не дублюецца ў `days`/`liturgicalProperTexts`; новых шаблонаў няма.
* Старыя кліенты (Flutter да падтрымкі) ігнаруюць невядомае поле і чытаюць плоскія палі.
* Валідацыя: `src/utils/ordo/commonSeasons.js` → `validateSeasonalVariants` (дазволеныя сезоны, вядомыя палі
  `OFFICE_CONTENT_FIELDS`, тыпы, HTML, памер, пакінутая ў тэксце рубрыка кнігі «(Велікодны перыяд Аллелюя)»,
  «У Вялікі пост:»); выкарыстоўваецца генератарам і валідатарам публікацыі (`DOCUMENT_RULES.liturgicalTemplates`).

## Які сезон

Сезон бярэцца з **Ordo выбранага Office** (`resolved.period`, `resolved.periodPhase` = `computeSeason`
даты), не па колеры, назве святога ці дыяпазону дат.

| Ordo | варыянт |
|---|---|
| `advent` | `advent` |
| `christmas` (25.12 – Хрышчэнне Пана) | `christmas` |
| `lent` | `lent` |
| `holyweek`, фазы `palm-sunday` / `holy-week` | `lent` |
| `holyweek`, фаза `triduum`, або фаза невядомая | няма (база) |
| `easter` (Уваскрасенне – Пяцідзясятніца) | `easter` |
| `ordinary` | няма (база) |

Рашэнне пра Вялікі тыдзень (NR-011, пацверджана рэдактарам): рубрыка тома II — «У Вялікі пост»; Quadragesima ідзе да Імшы
Вячэры Пана, таму Пальмовая нядзеля і панядзелак–серада бяруць тэксты Вялікага посту; Трыдуум не пост і не Вялікдзень.
Фактычныя пераходы Ordo (`computeSeason`, правяраюцца `tests/common-seasons-reaudit.test.mjs` для 2020–2060): Пальмовая
нядзеля — `holyweek/palm-sunday`, панядзелак–серада — `holyweek/holy-week`, **з даты Вялікага чацвярга** — `holyweek/triduum`
(да Вялікай суботы), Уваскрасенне — `easter/octave`. Ordo пераключае фазу па ДАТЕ, не па гадзіне Імшы Вячэры Пана, таму раніца
Вялікага чацвярга (па кнізе яшчэ Пост) чытае плоскі тэкст; але ніводнае Common-Office не цэлебруецца ў Вялікі тыдзень/Трыдуум
(тэст па календары 2026–2060, чатыры дыяцэзіі), таму гэтае рашэнне ніколі не вырашае рэальнае свята. Вырашае **фаза**, не перыяд:
`variantKeyForSeason({ period: 'holyweek' })` без фазы вяртае `null`.

I Нешпары бяруць сезон **самога празднавання** (яго даты): кантэнт I Нешпараў збіраецца ў тым жа
`assembleOffice` для даты празднавання.

## Выбар і прыярытэт (веб)

`materializeCommonForSeason(template, officeSeason)` — чыстая функцыя: бярэ плоскі шаблон і вяртае звычайны
плоскі аб'ект (без `_seasonalVariants`, з `_seasonal: { variant, fields }`); аргумент і кэш ніколі не мутуюцца;
без дэльты вяртае той жа аб'ект. `assembleOffice({ …, season })` чытае Commons праз
`seasonalTemplateGetter` (мемарызуецца на адзін выклік), таму ўсе шляхі (`fromTemplate`, `_fieldRules`
`source: common|template`, `vesper1*`, `allowCurrentDay`) бачаць сезонны тэкст, а `current-day`, `sunday-week-1`,
`complementary` — не. Парадак: свой Proper (`liturgicalProperTexts`) → `_fieldRules` → Common (з сезонам) → дзень.
Памятка «З дня» не змяняецца. Провенанс: `provenance[field] = 'common:<id>'`, а сезонныя палі —
`result.seasonal.fields[field] = '<variant>'` і `day._assembly.season`.

Кэш: сезонны тэкст ніколі не трапляе ў агульны `liturgicalTemplates`-кэш; зборка робіцца на выклік. Кэш
сабранага кантэнту ключуецца датай і дыяцэзіяй (`contentKey`), таму сезоны розных дат не змешваюцца. Пасля
імпарту шаблонаў у Firestore трэба павысіць `CONTENT_REVISION` (`npm run content:version:bump`), інакш ужо
збераджаныя ў браўзеры дні застануцца без сезонных тэкстаў.

## Адмінка

`DayEditor.vue` паказвае сабраны Office (read-only прагляд) з падказкай «сезонны варыянт: …» і правіламі;
запіс заўсёды пераходзіць у ўласны тэкст Proper (`sparseUpdatePayload`), сабраны сезонны HTML ніколі не
пішацца ў базавы плоскі тэкст. **Рэдагаванне саміх `_seasonalVariants` у інтэрфейсе не рэалізавана** (занадта
вялікі UI): праўце `patchs/feasts/common-texts/*.json` і ганяйце парсер/генератар. Гэта сведчыць пра
свядомую недарабоўку, а не пра адсутнасць функцыі.

## Парсер і крыніцы

Крыніцы: `patchs/sources/common-seasons/0{1,2,3}_*_utf8.txt` (sha256 у
`tests/common-seasons-parser.test.mjs`; арыгіналы `.doc` — у сумесным архіве).

```bash
node scripts/liturgy/common-seasons.mjs --dry-run --report   # аналіз; піша ТОЛЬКІ адчэты reports/liturgy/common-seasons-audit.{json,md} і common-seasons-base-corrections.md (common-texts не чапае)
node scripts/liturgy/common-seasons.mjs --check              # exit 1, калі common-texts не адпавядае парсеру
node scripts/liturgy/common-seasons.mjs --write              # абнавіць _seasonalVariants + patchs/sources/common-seasons/provenance.json
npm run generate:fixed-feasts                                # патч db-templates (толькі кэш, без Firestore)
node scripts/liturgy/common-seasons-import-plan.mjs          # план імпарту супраць лакальнага snapshot
node scripts/liturgy/common-seasons-fixture.mjs              # паритэтны fixture для Flutter
```

Парсер **параўноўвае цэлыя раздзелы** трох тамоў: `Common → гадзіна → поле → тэкст` (`lib/compare.mjs`, `lib/analyze.mjs`):

* Том III — база (Звычайны перыяд), том I — Адвэнт і Нараджэнне Пана, том II — Вялікі пост і Велікодны перыяд.
  Тэкст без лакальнай прыметы сезона **не** лічыцца роўным тэксту тома III: напечатаны ў поўным выглядзе раздзел сезоннага
  тома параўноўваецца са словамі раздзела тома III (пунктуацыя, рэгістр, апострафы, чырвоныя знакі `*` `†` `/`, спасылкі «с. NNN»
  — не словы).
* Рознасць класіфікуецца ў шэсць класаў (па-руску ў аўдыце): 1 арфаграфія/тыпаграфіка; 2 лексічная адрозніца аднаго тэксту
  (дробная — `minor`, істотная); 3 іншы тэкст (чытанне, псалом, гімн, малітва, антыфона, рэспансорый, К./Н.-радок);
  4 іншы склад (менш альтэрнатыў — «subset», адсылка замест тэксту, куплет, надрукаваны толькі адным томам);
  5 яўна сезонная (рубрыка «У Вялікі пост:» і г. д.); 6 нявырашанае (зараз 0).
* **Клас 3 (і клас 4 з чужымі элементамі)** становіцца сезонным варыянтам **ЦЭЛАГА поля**: заменай ідзе ўсё поле (загаловак,
  спасылка, тэкст, заключная формула, рэспансорый), без пошуку фразы рэспансорыя ўнутры чытання з іншага тома. Абсяг дзеяння
  тэксту — сезоны яго тома (I: `advent` + `christmas`; II: `lent` + `easter`), калі ў раздзеле няма сезонных рубрык; даказваецца
  рубрыкай у тым жа блоку (`(Велікодны перыяд Аллелюя)` у рэспансорыі чытання азначае: блок чытаецца і ў Пост, і ў Вялікдзень).
  Тэкст не «распаўсюджваецца» на два сезоны без такога доказу: яўныя падраздзелы «У Вялікі пост / У Велікодны перыяд» застаюцца
  асобнымі.
* Класы 1, 2 і падмноства/адсылка (4) **не** становяцца варыянтам: застаецца база (том III) з запісам у матрыцы
  (`reports/liturgy/common-seasons-audit.json`: `difference`, `resolution`, `sameAsOtherSeasonalVolume`). Усе словы, якія
  друкуе том I/II і якіх няма ў тэксце сезона, пералічаны (`wordCoverage`).
* Яўныя ўмовы па-ранейшаму: радкі «У Вялікі пост:/У Велікодны перыяд:/У перыяд Адвэнту:/У перыяд Нараджэння Пана:»,
  інлайн-ярлыкі «1 ант. у Вялікі пост:», сезонныя антыфоны пасля агульнага псальма, сезонны блок (марка + новы кампанент).
* Спадкаванне: раздзел `doctors-of-church` кожнага тома пачынаецца «Усё з Агульных тэкстаў пра пастыраў, … акрамя наступнага»;
  палі, якіх раздзел не друкуе і якія ў базе роўныя полю `pastors`, атрымліваюць сезонны тэкст `pastors` таго ж тома.
* Тэкст змененага поля рэндэрыцца ў стылі існуючага HTML (чырвоныя рубрыкі, `*`, `†`, `/`, `К.`, `Н.`, выраўноўванне і
  загаловак берацца з базы таго ж Common); нязменная частка (напр. чытанне перад кароткім рэспансорыем) — з існуючага HTML.
* Індэкс антыфонаў у канцы тома не парсіцца, але правяраецца: кожная яго пометка «(Велікодны перыяд Аллелюя)» мае пару ў корпусе.

### «(Велікодны перыяд Аллелюя)» (NR-001, прынята)

Гэта рэдакцыйны загад **для аднаго элемента**, пасля якога стаіць. Антыфона: «…тэкст, / аллелюя.» (форма, якую кніга сама друкуе
ў 26 велікодных антыфонах); антыфона, што канчаецца «!» — «…! / аллелюя.» (адзін выпадак, NR-002); радкі К./Н. і Н.-радок
рэспансорыя — «…, аллелюя.» (так заканчваюцца велікодныя рэспансорыі тома II, напр. «Н. Апосталы з вялікай моцаю … ласку,
аллелюя.»); кароткі «адказ» («Н. Яна выбрала.») не змяняецца, бо тамы яго не пазначаюць. Правіла ніколі не ставіцца глабальна.
Калі ў базавым тэксце аллелюя ўжо ёсць, яна не дублюецца і не выдаляецца па-за Вялікім постам; у Вялікі пост здымаецца толькі
там, дзе том II не друкуе яе (напр. `church-dedication.laudesAntBen`). «†» пасля пометкі належыць псальмодыі і ў антыфону
не пераносіцца (NR-002).

### Выпраўленні тэкстаў

* Базавыя (асобныя рэдакцыйныя камітэты, не сезонныя варыянты): `officeOfReadingsVers` у `apostles`, `virgins`, `holy-women`
  (К./Н. перастаўлены ў томе III; у `holy-women` памылку паўтарае і том II, верны толькі том I) і антыфоны Пс 64 (63) у
  `apostles` (NR-003). Паказальнік: `baseCorrections` у аўдыце.
* Друкарская памылка тома II «аллеюя» → «аллелюя» (3 радкі: 118, 527, 1167) выпраўляецца ў сезонных тэкстах (NR-010).
* `--include-unverified` выдалены: нязацверджаныя выпраўленні ніколі не ўключаюцца пераключальнікам; невядомы аргумент
  скрыпта — памылка (exit 2). Усё, што генерыруецца, або надрукавана томам, або вынікае з правіла, прынятага рэдактарам.
