# Пилот: отдельный формат Литургии часов для пяти набажэнстваў (WEB)

## Scope

Только чтение и предпросмотр в веб-редакторе для:
1. Ютрань за памерлых;
2. Нешпары за памерлых;
3. Ютрань да Маці Божай;
4. Нешпары да Маці Божай;
5. Гадзінкі да Найсвяцейшай Панны Марыі.

У базы Firestore ничего не изменяется. Тексты, роли, переносы, рубрики, ссылки, языковые версии, ID и доступы не мигрируются. Основная молитва Святой Мессы и все остальные молитвы продолжают использовать прежний рендерер.

## Design

- Вводится читательский профиль `devotional-office`, аналогичный **по принципу**, но не по правилам и ролям адаптеру Святой Мессы.
- Красным `--rubric-color` окрашивается **только маркер** `1 ант.` / `Ант. 1.`, но не произносимая строка антифона.
- Антифон отдельным абзацем получает мягкую рубричную подложку и левую черту.
- Настоящие заголовки Markdown и отдельные подтверждённые названия разделов (псальмодыя, гімн, кароткае чытанне, кароткі рэспансорый, просьбы…) становятся рубричными заголовками только **при отображении**.
- `V.`, `R.`, `К.`, `Н.` продолжают использовать существующий контракт `prayer-speaker`.
- Дополнительные тексты и альтернативные варианты отмечаются визуально; **не** создаётся автоматический переключатель, пока не установлено, что варианты литургически взаимозаменяемы. Никакие фрагменты не скрываются.

## Verification gate — BEFORE MERGE

Сейчас профиль включается строго через узнавание заголовков молитв, поскольку подтверждённых пяти Firestore document IDs в репозитории нет. Эту эвристику необходимо заменить на проверенные IDs (или явный контролируемый presentation flag) после получения актуального разрешённого snapshot. Пока данных нет, ветку не вливать в main.

1. Проверить реальные ID, названия и версии текста всех пяти документов; подтвердить, что именно пять документов получают профиль и нет ложных совпадений.
2. Пройти каждую молитву полностью. Удостовериться, что заголовки/антифоны/библейские ссылки/респонсории/варианты корректно интерпретированы и ничего не пропало.
3. Сравнить text-only проекцию до/после. Проверить, что обратное редактирование не изменяет исходник.
4. Проверить светлую/тёмную тему и 320, 390 px со скейлом 200%, длинные названия и переносы.
5. Сверить предпросмотр редактора с публичным reader, затем тестировать на preview hosting; в production не деплоить без отдельного решения.
6. Выполнить `node --test tests/devotional-office.test.mjs tests/prayer-markdown.test.mjs`, `npm run build`.

## Known limits

- Это профиль вывода. В отличие от настоящей Літургіі гадзінаў, здесь нет переключателей антифонов/вариантов, псалмового чередования и особой навигации по блокам.
- Неразмеченные нестандартные заголовки и формы меток антифонов потребуют добавления после изучения реальных документов.
- Использование заголовка вместо ID — исключительно временная мера для пилота; контракт должен стать ID-based.
