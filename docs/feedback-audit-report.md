# Аудит обратной связи: матрица точек входа и отчёт о тестах (2026-11-13)

Охват: Web (`senddownrain/mybrev`), Flutter (`senddownrain/ibreviarybyapp`), общий Worker. Production не затрагивался: экспорт и исправление идемпотентности лежат в Worker и **не развёрнуты** (нужен `wrangler deploy` по слову владельца); политика конфиденциальности и клиентские изменения попадут в production только вручную запущенным деплоем Web и новой сборкой Flutter.

Легенда: **PASS** — проверено (автотест и/или на экране); **PASS (unit)** — только автотест маршрута, на экране не открывал; **NOT TESTED** — не проверялось; **N/A** — экрана нет.

Контекст (только публичный и проверяемый): `kind`, `id`, `title` (только где известно, как у молитвы), `date`, `hour`, `diocese` (Flutter — id диоцеза читателя), `lang`, `path` (Web — путь страницы для «Вярнуцца да чытання»). Не передаются: избранное, история чтения, текст документа, личные данные. `translation`/`cycle` в контекст **не добавлены**: для этого нужно расширять allowlist Worker (отдельная совместимая миграция); решение отложено до подтверждения владельца.

## Результаты тестов

**Web**
* `node --test workers/feedback/test/*.test.mjs` — 17/17 (+2 новых: реюз `requestId` → 409 при другом тексте, идентичный повтор идемпотентен; экспорт: ролевая область, отсутствие email/телефона/ссылок, CSV formula-guard, валидация, 401/403).
* `npm run test:feedback` — 22/22.
* `npm test` — 1218 pass, **2 fail** (`fixedCalendar fixes found by stage 2`, `Bible, Readings and all Hours have no old source footers…`): те же 2 падают на чистом `main`, к изменению не относятся.
* `npm run lint` — чисто; сборка — OK.
* `npm run test:feedback-e2e` — публичные сценарии (форма, ошибка/повтор, лог Worker без текста) **PASS**; сценарии админки и API (5 шт.) **FAIL**, как и на чистом `main` до изменений (окружение эмуляторов; причина не расследовалась). Поэтому мобильная карточка обращения и кнопки экспорта в админке **NOT TESTED в браузере**; экспорт покрыт тестами Worker.
* Реальный браузер (встроенный, mock Worker): форма на 390 и 320 px, светлая/тёмная схема, без горизонтального прокручивания; найден и исправлен реальный дефект 320 px (поле и чипсы шире экрана). Снимки: `docs/feedback-evidence/audit/`.

**Flutter** (отдельный PR)
* `flutter test test/feedback` — 19/19; `flutter analyze` — 0 ошибок.
* Полный прогон: 1904 pass, 29 fail; на чистом `main` — 1895 pass, те же 29 fail (parity часов и лекционария, readings/«shared value, safe panel» и др.).
* iOS Simulator (iPhone 16): первая сборка показала дефект — на странице, открытой через `context.push`, пункт «Памылка» не появлялся (router отдавал адрес страницы под ней); исправлено (учёт `ImperativeRouteMatch`), после пересборки пункт и форма с контекстом подтверждены на устройстве, снимки в PR. В production-Worker тестовые сообщения **не отправлялись**.

## Не проверено (честно)
* Android (эмулятор/устройство), настоящий iPhone.
* Марийская тема и крупный системный шрифт (Web и Flutter); 320 dp на iOS; TalkBack/VoiceOver.
* Мобильная карточка обращения и экспорт в админке на экране; роли в живом Firebase.
* Все материалы, кроме перечисленных «браузер PASS»/«iOS PASS», — только автотесты маршрута.

## Релиз и откат
* Worker: `wrangler deploy` (экспорт и защита `requestId` — обратно совместимы: схема D1 не меняется, миграции нет); откат `wrangler rollback`. Старые клиенты не ломаются: они присылали тот же `requestId` с тем же текстом.
* Web: ручной запуск `Deploy Web to Firebase Hosting`. Flutter: новая сборка.
* Вложения (скриншоты): `docs/feedback-attachments-phase2.md`, не блокирует релиз.
