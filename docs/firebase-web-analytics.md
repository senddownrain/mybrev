# Google Analytics for Firebase — Web (draft)

This integration is independent of the existing local/Cloudflare analytics.
It uses the installed Firebase JS SDK and does not write to Firestore.

## Default behavior

No analytics SDK initialization in ordinary builds. The build gate is
`VITE_FIREBASE_ANALYTICS=true` and the runtime gate is a recorded explicit
opt-in (`mybrev_google_analytics_consent_v1=granted` in localStorage).
A missing measurement ID or unsupported browser also prevents initialization.

The draft logs only a generic initial page_view, not individual prayers,
routes, user IDs, access codes, or search terms. Automatic Firebase/GA
events may still be generated by the SDK. Advertising consent is denied
and advertising signals are disabled in the initial configuration.
These are configuration intentions, not a verified network privacy guarantee.

## QA (test stream and synthetic traffic only)

1. In Firebase Project Settings > Your apps, confirm the Web app's
   measurement ID. Set VITE_FIREBASE_MEASUREMENT_ID in the test build.
2. In GA Admin > Data Streams > Web, switch Enhanced Measurement OFF,
   and disable Google signals and advertising personalization.
3. Build with VITE_FIREBASE_ANALYTICS=true. In a test browser only,
   explicitly set the test opt-in in DevTools and reload:
   `localStorage.setItem('mybrev_google_analytics_consent_v1', 'granted')`.
4. Check GA Realtime/DebugView and inspect actual network requests on
   initial loading and navigation. Confirm no prayer identifiers, paths,
   titles, search terms, private routes or sensitive referrers are sent.
5. Remove the test key, close the test page and reload; confirm no
   Analytics SDK is initialized. Never use the test key to bypass user choice.

## Before real-user activation

This is a draft technical preparation, not authorization to enable collection.
Implement a user-facing choice with immediate withdrawal, including already
initialized tabs; review the privacy notice and applicable consent requirements;
verify real SDK payloads, including automatic events and enhanced measurement
settings; ensure the production measurement ID is correct. Do not enable the
production build flag until those checks pass. No changes are required to
Firestore rules, collections, Cloudflare workers or databases.

Unit tests: `node --test tests/google-analytics.test.mjs`.
Run the normal production build and smoke tests as well.
