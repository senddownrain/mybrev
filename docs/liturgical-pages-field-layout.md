# Автономная спецификация интерфейса чтений и Литургии часов

## Назначение

Этот файл можно передать нейросети без доступа к исходному приложению. Он описывает коллекции, порядок блоков, повторы антифон, условия отображения и оформление. Тексты полей могут содержать HTML (`p`, `br`, `span`, `em`, `strong`, inline-стили); их нужно безопасно санитизировать, сохраняя литургическое форматирование.

## 1. Коллекции

### `fixedDays`

Основные документы дней и праздников с текстами часов. Селекторы: `_periodType`, `_periodWeekNumber`, `_dayOfWeek`, `_date` (`DD.MM`), `_feast`. Метаданные заголовка: `_title`/`_feastName`, `_rank`/`_feastType`, `_place`, комментарий. Содержит поля `officeOfReadings*`, `laudes*`, `sext1*`, `sext2*`, `sext3*`, `vesper*` и `vesper1*`.

### `parsedData`

Структурированные литургические чтения. Селекторы: `_dayId`, `_dayIds`, `_feast`, `_date`, `_periodType`, `_periodWeekNumber`, `_dayOfWeek`, `year`. Контент: `title`, `reading1`, `psalm`, `reading2`, `alleluia`, `gospel`.

### `invitatoriums`

Варианты псалма приглашения: `title`/`name` и `invitatoriumPs1…invitatoriumPs6`; Ps5 и Ps6 необязательны. Антифона `invitatoriumAnt` берётся из выбранного литургического дня.

### `completoriums`

Отдельные документы Камплеты с ID `{periodType}-d{dayOfWeek}`, где 1 — воскресенье, 7 — суббота. Поля: `compHymn`, `compAnt1…3`, `compPs1`, `compR`, `compResp`, `compAntS`, `compPr`, `compAntM`.

Для торжеств и праздников выбирать воскресный `d1` текущего периода. Для `holyweek` использовать период `lent`.

## 2. Выбор и сборка дня из `fixedDays`

Для даты вычислить `periodType`, номер недели, день недели 1…7, будничный цикл 1/2, воскресный цикл A/B/C и переходящие праздники.

Приоритет источников:

```text
выбранное празднование
→ фиксированная дата или переходящий праздник
→ обычный день периода
```

Правила:

1. Поля выбранного празднования имеют приоритет.
2. Поле празднования с маркером «взять из обычного дня» заменить одноимённым полем обычного дня из `fixedDays`.
3. Намеренно пустое поле не заполнять, если оно не помечено как наследуемое.
4. Технические маркеры не должны попадать в UI.
5. Для 17–24 декабря три антифоны могут храниться тремя HTML-абзацами в поле дня недели (`sunday`…`saturday`). Разложить их в `laudesAnt1…3` и `vesperAnt1…3`.
6. При нескольких празднованиях на дату дать пользователю выбрать одно.
7. Все тексты часов для обычного дня, праздника или сезонного исключения брать только из документов `fixedDays`.
8. Если периодический документ `fixedDays` отсутствует, считать день отсутствующим: не создавать его из другого источника.
9. Если содержательное поле `fixedDays` пустое, оставлять его пустым и не показывать соответствующий блок. Не дополнять его шаблонами.

## 3. Общая оболочка часа

```text
Литургический период
Название дня / праздника
Дата · ранг
Комментарий — если есть

НАЗВАНИЕ ЧАСА
Вступление
Собственные блоки часа
Заключение
```

Стандартное вступление:

```text
К. Божа, прыйдзі мне на дапамогу.
Н. Пане, паспяшы да мяне на паратунак.
Хвала Айцу і Сыну, * і Духу Святому.
Як была спрадвеку, цяпер і заўсёды, *
і на векі вечныя. Амэн.
Аллелюя.
```

Пустое необязательное поле не создаёт блок. Заголовки, уже находящиеся внутри HTML, не дублировать.

## 4. Универсальный алгоритм псалмодии

Вход: `ant1/ps1`, `ant2/ps2`, `ant3/ps3`.

### Обычный режим

Каждая антифона выводится два раза:

```text
ant1 → ps1 → ant1
ant2 → ps2 → ant2
ant3 → ps3 → ant3
```

### Одна антифона на три псалма

Если `ant1` и все три псалма есть, а `ant2` и `ant3` пусты:

```text
ant1 → ps1 → ps2 → ps3 → ant1
```

Не повторять `ant1` между псалмами.

### Дополнительные правила

- Не выводить пустые псалмы и связанные с ними антифоны.
- Если `ps3` содержит варианты, показать переключатель и только активный вариант между двумя `ant3`.
- Убирать лишний перенос строки сразу после символа `*`.
- Заголовок блока: `ПСАЛМОДЫЯ`.

## 5. Заклік / Invitatorium

```text
Заголовок дня
├── выбор варианта из invitatoriums — если вариантов больше одного
├── ЗАКЛІК
│   ├── пояснительная рубрика
│   ├── К. Пане, адкрый мае вусны.
│   └── Н. І вусны мае будуць абвяшчаць Тваю хвалу.
└── псалом приглашения
```

Алгоритм: перед каждой непустой частью `invitatoriumPs1…6` показать `invitatoriumAnt`, после последней части повторить антифону ещё раз.

```text
Ant → Ps1 → Ant → Ps2 → Ant → Ps3 → Ant → Ps4 → Ant
```

При наличии Ps5/Ps6 продолжать так же. Название варианта: `title → name → номер псалма из Ps1 → «Псальм N»`.

## 6. Гадзіна чытанняў

```text
Заголовок дня
├── ГАДЗІНА ЧЫТАННЯЎ + вступление
├── ГІМН                         officeOfReadingsHymn
├── ПСАЛМОДЫЯ                    officeOfReadingsAnt1…3 / Ps1…3
├── Верш / рэспансорый           officeOfReadingsVers
├── Первое чтение                officeOfReadingsR1
├── Второе чтение                officeOfReadingsR2
├── МАЛІТВА                      officeOfReadingsPr
└── краткое заключение
```

`R1` и `R2` — готовый HTML, обычно уже содержащий название чтения, источник, ссылку, текст и рэспансорый. Внешние заголовки не добавлять.

## 7. Ютрань

```text
Заголовок дня
├── ЮТРАНЬ + вступление
├── ГІМН                         laudesHymn
├── ПСАЛМОДЫЯ                    laudesAnt1…3 / Ps1…3
├── краткое чтение/рэспансорый   laudesR
├── ПЕСНЯ З ЕВАНГЕЛЛЯ
│   └── laudesAntBen → Песня Захарии → laudesAntBen
├── ПРОСЬБЫ                      laudesInter
├── «Ойча наш»                   статический текст
├── МАЛІТВА                      laudesPr
└── благословение / отпуст
```

Антифона к Песне Захарии всегда показывается до и после песни.

## 8. Дневные часы

Одинаковая схема для трёх страниц:

```text
Название + вступление
ГІМН
ПСАЛМОДЫЯ
Краткое чтение
МАЛІТВА
Краткое заключение
```

| Час | Название | Префикс полей |
|---|---|---|
| Перед полуднем | `МАЛІТВА ПЕРАД ПОЎДНЕМ` | `sext1` |
| В полдень | `МАЛІТВА АПОЎДНІ` | `sext2` |
| После полудня | `МАЛІТВА ПАСЛЯ ПОЎДНЯ` | `sext3` |

Суффиксы: `Hymn`, `Ant1…3`, `Ps1…3`, `R`, `Pr`.

Для каждого отдельного поля `sext2*` и `sext3*`: если собственное значение пусто, взять соответствующее `sext1*`. Не заменять весь час целиком из-за одного отсутствующего поля.

## 9. Нешпары

```text
Заголовок дня
├── НЕШПАРЫ + вступление
├── ГІМН                         vesperHymn
├── ПСАЛМОДЫЯ                    vesperAnt1…3 / Ps1…3
├── краткое чтение/рэспансорый   vesperR
├── ПЕСНЯ З ЕВАНГЕЛЛЯ
│   └── vesperAntMag → Песня Марии → vesperAntMag
├── ПРОСЬБЫ                      vesperInter
├── «Ойча наш»
├── МАЛІТВА                      vesperPr
└── благословение / отпуст
```

Если `vesperPr` — пустая строка, использовать `laudesPr`. Первые Нешпары могут храниться как `vesper1*`; перед рендером выбранные первые или вторые Нешпары привести к единому набору `vesper*`.

## 10. Камплета

```text
Заголовок дня
├── КАМПЛЕТА + вступление
├── Рахунак сумлення             статическая рубрика
├── ГІМН                         compHymn
├── ПСАЛМОДЫЯ                    compAnt1 → compPs1 → compAnt1
├── краткое чтение               compR
├── рэспансорый                  compResp
├── ПЕСНЯ З ЕВАНГЕЛЛЯ
│   └── compAntS → Песня Симеона → compAntS
├── МАЛІТВА                      compPr
└── заключение + антифона Марии  compAntM
```

## 11. Агульная гадзіна

Объединённая последовательность «Заклік + Гадзіна чытанняў + Ютрань»:

```text
Заголовок дня
├── АГУЛЬНАЯ ГАДЗІНА — без стандартного вступления
├── Заклік: выбор → диалог → Ant/Ps1…6/Ant
├── laudesHymn
├── officeOfReadingsAnt/Ps1…3
├── officeOfReadingsVers
├── officeOfReadingsR1
├── officeOfReadingsR2
├── laudesAnt/Ps1…3
├── laudesR
├── laudesAntBen → Песня Захарии → laudesAntBen
├── laudesInter
├── «Ойча наш»
├── laudesPr
└── благословение / отпуст
```

Между вторым чтением и Ютранью не показывать молитву и заключение Гадзіны чытанняў.

## 12. Литургические чтения

### Выбор `parsedData`

Приоритет кандидатов:

```text
1. связь с выбранным днём: _dayId / _dayIds
2. переходящий праздник: _feast
3. фиксированная дата: _date = DD.MM
4. период: _periodType + _periodWeekNumber + _dayOfWeek
```

Циклы: A/B/C для воскресений, 1/2 (показывать I/II) для будней, `year = null` — общий текст. Актуальный цикл даты выбирать автоматически. Альтернативные празднования и циклы показывать селекторами; отображать только один выбранный документ.

### Структура страницы

```text
ЧЫТАННІ
├── дата + маркер литургического периода
├── выбор празднования — если нужен
├── выбор цикла — если нужен
└── карточка
    ├── ЛІТУРГІЯ СЛОВА
    ├── title
    ├── year
    ├── reading1
    ├── psalm
    ├── reading2 — необязательно
    ├── alleluia — необязательно
    └── gospel
```

### Обычное чтение и Евангелие

Объект: `bible`, `comment`, `title`, `text`. Порядок: название раздела и `bible`, затем `comment` курсивом, `title` полужирным, затем основной текст. На мобильном `bible` переносится под название.

Если `text` начинается с той же ссылки, что `bible`, удалить повтор. Фразу «Гэта слова Пана/Божае» выделить полужирным и отделить сверху.

### Псалом

Поля: `bible`, `chorus`, `verses[]`, `altChorus`, резервный `text`.

```text
РЭСПАНСАРЫЙНЫ ПСАЛЬМ + bible
РЭФРЭН + chorus
строфа 1
РЭФРЭН + chorus
строфа 2
...
последняя строфа
АБО + altChorus
```

Если `altChorus` нет, после последней строфы ещё раз показать основной `chorus`. Если `verses[]` нет, показать `text` единым HTML-блоком. Удалить из `chorus` начальное слово `Рэфрэн:`, так как UI добавляет метку сам.

### Песнь перед Евангелием

```text
СПЕЎ ПЕРАД ЕВАНГЕЛЛЕМ
АКЛАМАЦЫЯ: Аллелюя, аллелюя, аллелюя.
verse; если нет — text
АКЛАМАЦЫЯ: Аллелюя, аллелюя, аллелюя.
```

Акламация показывается два раза.

## 13. Оформление

| Элемент | Правило |
|---|---|
| Контейнер | до `960px`, по центру, поля 12px; на мобильном около 8px |
| Основной текст | около `1.04rem`, пользовательский масштаб, интерлиньяж 1.75–1.8 |
| Заголовок блока | прописные, около `0.8rem`, жирность 800–850, увеличенный letter-spacing |
| Абзацы | нижний интервал около `1em` |
| Выравнивание | только влево; inline `justify` переопределять |
| Антифоны/рефрены | мягкий фон, левая граница, полужирный текст |
| Разделы | единая спокойная поверхность, тонкие разделители, без тяжёлой карточки на каждый блок |
| Мобильный вид | полная ширина, без горизонтального скролла |

Семантические цвета: `surface`, `on-surface`, `muted`, `border`, `primary`, `rubric`, `liturgical-period-color`. Красный inline-цвет из данных преобразовывать в `rubric` для светлой и тёмной темы.

Состояния каждой страницы: `loading`, `error + повтор`, `empty`, `ready`.

## 14. Отдельно: расхождения / TODO

Эти пункты не смешивать с основной спецификацией и не исправлять без отдельного решения.

1. `Te Deum` теперь выводится после второго чтения по календарному правилу; старое поле `officeOfReadingsTeDeum` не используется для рендеринга.
2. Камплета фактически использует только `compPs1`; `compPs2/3` не подключены.
3. `compAnt2/3` могут присутствовать без подключённых второго и третьего псалмов.
4. `laudesR` и `vesperR` могут объединять чтение и рэспансорый в одном HTML-поле.
5. `officeOfReadingsR1/R2` объединяют чтение и рэспансорый внутри одного HTML-поля.
6. «Ойча наш» сейчас является сокращённой статической строкой, не полным текстом.
7. Песни Захарии, Марии и Симеона, вступления и заключения находятся в UI, а не в коллекциях.
8. Первые и вторые Нешпары хранятся двумя наборами `vesper1*` и `vesper*`; нужна явная нормализация.
9. Альтернативы закодированы внутри строкового HTML; в будущем лучше хранить массивы объектов.
10. Устаревший механизм `dayTemplates` ещё может существовать в админских и служебных инструментах проекта, но не относится к контракту нового интерфейса и не должен читаться при отображении.

## 15. Чек-лист реализации

- [ ] Каждая обычная антифона показана до и после своего псалма.
- [ ] Одна общая антифона окружает всю группу псалмов, не каждый псалом.
- [ ] Антифоны Benedictus, Magnificat и Nunc dimittis повторены после песни.
- [ ] Антифона Invitatorium повторяется между частями и после последней.
- [ ] Рефрен псалма чтений повторяется между строфами и в конце по правилам.
- [ ] Аллелюя показано до и после стиха.
- [ ] Пустые разделы полностью пропущены.
- [ ] Циклы и альтернативные празднования не складываются подряд.
- [ ] HTML очищается, но абзацы, переносы и рубрики сохраняются.
- [ ] Интерфейс читаем в светлой и тёмной теме.
- [ ] Расхождения из раздела 14 остаются отдельными TODO.
- [ ] Все часы собираются только из `fixedDays`, `invitatoriums` и `completoriums`; устаревшие шаблоны дней не читаются.
