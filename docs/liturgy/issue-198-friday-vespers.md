## Диагноз и границы доказательства

Проверено 2026-11-07. Production Firestore `(default)` — STANDARD.
`backups/firestore-snapshot/manifest.json` отсутствовал. После проверки этого
условия выполнены разрешённые пользователем ограниченные GET-чтения:
метаданные базы, три документа из issue, затем ещё четыре `days` и действующий
`liturgicalProperTexts/01-11-all-saints` для воспроизведения `dayOptions`.

22 поля заполнены. Ни одно из этих пустых полей менять не требуется.

## Нормативная сверка

Сохранённое официальное белорусское «Агульныя ўводзіны»:
[`lh-introduction-2026-11-06.txt`](../sources/primary/lh-introduction-2026-11-06.txt),
§§ 53, 119, 126, 133, 157: обычные будни берут молитву и антифон из
Псалтыра; его цикл — четыре недели. XXX неделя соответствует II неделе.
Проверка самой псалмодии по первичному источнику епископской конференции:
[Liturgy Office, Table of Psalms, Week II / Friday / Evening](https://liturgyoffice.org.uk/Resources/Hours/4-week-psalter.pdf)
— Ps 114, 120, Rev 15 в нумерации этого издания. Это Ps 116, 1–9 (114),
Ps 121 (120), Ап 15, 3–4 в белорусском `ordinary-w2-d6`.

Белорусские тексты переносятся без редактирования из существующего документа
Псалтыра. Побуквенную сверку всех переводов с печатным белорусским томом эта
проверка не заменяет; онлайн-страница `lh.catholic.by/showalldates` через
доступный web-инструмент не открылась. Нормативно сверены выбор недели и
псалмодия; принадлежность всех 11 ошибочных полей празднику доказана точным
сравнением документов.

## Ordo, UI и регрессии

Offline replay использует ограниченный локальный snapshot реальных документов,
`contentFor` → `assembleDaysResult` → `buildOrdoDayOptions` →
`eveningVespersModel`, до и после применения плана **в памяти**.
Он использует действующий Proper из Firestore, без подмены generated Proper.
36 случаев (9 дат × 4 диоцезии) прошли; накануне Усіх Святых дополнительно
сверены все 11 полей с `vesper1*` действующего Proper.

| Дата | Решение Ordo | Результат плана |
| --- | --- | --- |
| 2025-10-30, 2026-10-29 | свой день | без изменений |
| 2025-10-31, 2026-10-31, 2027-10-31 | I Нешпары Усіх Святых | без изменений, источник — завтрашний Proper |
| 2026-10-30, 2027-10-29 | свой день | вместо загрязнённого текста — пятница II недели |
| 2027-10-30 | I Нешпары XXXI нядзелі | без изменений |
| 2027-11-01 | II Нешпары Усіх Святых | без изменений |

Тесты с синтетическими распознаваемыми текстами дополнительно покрывают
2028-10-27/30/31, 2028-11-03, другую пятницу (2026-01-23) и все диоцезии.
**2028-11-03 тоже использует `ordinary-w30-d6`**: тот же патч исправляет и
эту дату. Исправление относится ко всем обычным пятницам XXX недели;
законный вечер другого празднования продолжает выбирать Ordo.

`periodPsalterFallbackId` дополняет недостающие дневные поля и не заменяет
заполненные Нешпары. Безопасной ссылки из этого legacy-документа на
произвольный документ Псалтыра текущая модель не предоставляет:
`_fromDayFields` означает поля текущего дня при сборке празднования.
Поэтому здесь нужен узкий перенос существующих строк, без новой схемы.
Календарь 01.11, вычисление недели и UI менять не требуется.

## План, резервирование и применение

```bash
# Без сети; по умолчанию scripts/lib/firestore-snapshot.mjs читает обычный snapshot.
node scripts/liturgy/fix-ordinary-friday-vespers.mjs --snapshot backups/issue-198/snapshot \
  --out reports/liturgy/issue-198-reviewed-plan.json
node scripts/liturgy/audit-ordinary-friday-vespers.mjs --snapshot backups/issue-198/snapshot

# Явное ограниченное чтение production: 3 документа, никаких записей.
node scripts/liturgy/fix-ordinary-friday-vespers.mjs --live \
  --out reports/liturgy/issue-198-fresh-plan.json
```

Планы и копии документов приватны, игнорируются Git, создаются с правами 0600
без перезаписи существующего файла. Полный snapshot не экспортируется.
Локальный ограниченный snapshot этой проверки содержит 7 `days` и 1 Proper;
это не полный корпус для сборки приложения или публикации манифеста.

**Только после отдельного разрешения владельца на запись:**

```bash
node scripts/liturgy/fix-ordinary-friday-vespers.mjs --live --apply \
  --plan reports/liturgy/issue-198-reviewed-plan.json
```

Применение перечитывает три документа и требует точного совпадения с
проверенным планом. Неизвестный текст, пустой источник, неправильные селекторы
или изменённый updateTime приводят к отказу. Перед commit сохраняется
резервная копия всех трёх документов (включая raw REST-представление).
Одна атомарная операция содержит две `verify` для Псалтыра/праздника и один
`update` с `updateMask` только 11 полей и `updateTime` исходной пятницы.
После записи — повторное чтение и сравнение всего документа, включая
нетронутые поля. Ошибка проверки требует ручного анализа, не автоматического
отката поверх возможных чужих изменений. Повторный dry-run после успешной
записи даёт пустой план; старый план повторно применить нельзя.

проверку на Android/iOS после публикации ещё предстоит выполнить.

После разрешённой записи обязательно:

1. Проверить `npm run content:manifest -- --collection days` (live dry-run)
   с действительными credentials по принятому в проекте способу.
   Убедиться, что diff содержит ожидаемую пятницу, а другие неопубликованные
   изменения не попадут в публикацию случайно. Ограниченный snapshot из этой
   проверки для этого **не годится**.
2. Публиковать `content:manifest -- --collection days --apply` только при
   SAFE CONTENT PATCH и после разрешения на эту запись. Приложение получает
   документ по изменённому хешу, проверяет его и активирует через ContentStore.
   Не пересобирать весь bundle и не удалять Hive/settings/избранное.
3. После записи поднять `CONTENT_REVISION` штатным `content:version:bump`

   offline остаётся доступным предыдущий текст до успешного обновления.
4. Проверить указанные даты в web/PWA и Flutter после получения патча,
