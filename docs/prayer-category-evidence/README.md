# Подкатегории: реализация и приёмка

PR #246 обновлён по утверждённому 14.11.2026 решению: навигация по страницам
категорий полностью заменяет аккордеоны. Ветка перебазирована на актуальный
`origin/main` **3ea571d**; merged PR #247 (**17d8eb6**) интегрирован вместе с
`iconKey`, 48 иконками, picker, allowlist и SVG. Ветка/PR остаются прежними.

## Что изменилось

- Боковая панель показывает только корни видимого дерева и личные категории.
  У каждой — собственный `CategoryIcon`; обычная ссылка сразу открывает категорию.
- Страница: название/ссылка к видимому родителю или «Усе малітвы» → все видимые
  непосредственные подкатегории с иконкой и стрелкой перехода → прямые молитвы.
  Папка без собственных молитв показывает детей без ложного empty-state.
  Отдельного пункта «Малітвы гэтай катэгорыі» нет.
- Прямые ссылки `/prayers?category=<Firestore-id>`, переходы через родителя,
  browser Back/Forward, заголовки, scroll и фокус поддерживаются на каждом уровне.
  На возврате фокус получает выбранная дочерняя категория или открытая молитва;
  дальнейший поиск не перехватывает фокус.
- Админское дерево всегда видно полностью с отступами и контекстом поиска.
  Создание/перенос/редактирование, ручной состав, теги, порядок и picker 48 иконок
  сохранены. `iconKey` переживает сохранение/reload вместе с membership и legacy
  метаданными. Удалены компонент `PrayerCategoryBranch`, `expandedCategoryKeys`
  и обработчики раскрытия дерева.
- Не менялись direct membership (`tags OR prayerIds OR legacy`, unique ID),
  границы родительского состава, сортировка, фильтрация пустых ветвей, fail-closed,
  Public/Priest/Admin, namespaces, атомарный мутатор и `priestContentControl`.
  Личные категории остаются плоскими; скрытый разрешённый родитель делает детей
  корнями. Скрытие меню не запрещает разрешённую прямую ссылку.

## Повтор и ручная приёмка

```sh
npx -y firebase-tools@latest emulators:exec --only auth,firestore --project demo-rules "node scripts/smoke-prayer-categories.mjs"
```

Для установленного CLI: `npm run smoke:prayer-categories`. Путь Chromium:
`BENCHMARK_BROWSER_PATH=/path/to/chromium`, по умолчанию `/usr/bin/chromium`.
Скрипт отказывается работать без localhost emulator hosts, использует только
project `demo-rules`; браузер блокирует все внешние HTTP-запросы. Его UI-role
harness не подменяет матрицу Rules — та отдельно проверяет реальные права.
Полный прежний rules/UI smoke запускается через `npm run test:priest:rules`.

1. Открыть админку: все уровни сразу видны с отступами и иконками. Поиск листа
   оставляет контекст родителей, три access фильтра работают. Раскрытия узлов нет.
2. В редакторе проверить 48 вариантов picker, выбрать собственный SVG-ключ,
   изменить manual membership и порядок, сохранить/reload. `iconKey`, молитвы,
   legacy `iconId` и остальные атрибуты сохраняются.
3. Добавить подкатегорию, перенести ветку, создать пустую папку. Запрещены
   self/cycle/missing parent, глубина >64 и удаление родителя с детьми.
   Удаление последнего тега сохраняет категорию, детей и manual IDs.
4. Public sidebar: только корни + personal. `Марыйныя малітвы` сразу открывает
   страницу, где `Ружанец` стоит перед собственными молитвами родителя.
   `Ружанец` → собственная молитва → reader → Back/Forward.
5. Повторить на дополнительном уровне `Таямніцы ружанца`, проверить ссылку к
   родителю, прямой URL и reload листа. Проверить scroll и фокус после истории,
   поиск/теговый фильтр после reader/back, избранное и личную категорию.
6. Папка с ребёнком и без своих молитв показывает только дочерние разделы.
   Скрыть родителя: разрешённые дети становятся корнями бокового меню и не
   возвращают скрытого родителя через навигационную ссылку.
7. Без grant закрытые названия/молитвы отсутствуют и deep link даёт недоступную
   категорию. Активировать локальный grant: закрытый родитель/ребёнок открываются
   страницами, свои/унаследованные молитвы доступны. Отозвать grant: данные
   исчезают. Транзакционные transfer/removed-link/400-write/stale/lock тесты
   подтверждают сохранение прежней политики доступа.
8. Проверить все темы на 320/375/768/desktop, tap targets, обычные links/keyboard,
   отсутствие accordion controls в меню и дереве (панель picker иконок допустима).

## Выпуск и Flutter

[Контракт и копируемый handoff](../prayer-categories-contract.md) обновлены под
страницы, `iconKey` и PR #247. Flutter не изменялся; migration script иконок
с production не запускался. Изменения исходников молитв/часов/календаря из
актуального main не редактируются этим PR.

Не выполнены merge PR, Hosting deploy, production Firestore apply или публикация
bundle/manifest. Порядок: согласование Web PR/контракта → Flutter PR/проверка
старого decoder → сквозная приёмка → отдельное решение владельца о выпуске.
