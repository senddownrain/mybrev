# MyBrev Markdown для малітваў

Крыніцай праўды для тэксту малітвы з'яўляецца Markdown, а не HTML і не JSON рэдактара.

## Фармат

Дакумент выкарыстоўвае звычайны CommonMark з невялікім пашырэннем для літургічных рубрык:

```md
## Малітва пасля Камуніі

**Памолімся.**

:::rubric
Усе моляцца некаторы час у цішыні.
:::

Божа, Ты насычаеш нас нябесным Хлебам...
```

Дазволеныя канструкцыі:

- абзацы і пустыя радкі;
- загалоўкі `##`–`######`;
- тлусты тэкст `**тэкст**` і курсіў `_тэкст_`;
- спісы і спасылкі CommonMark;
- блок рубрыкі ад асобнага радка `:::rubric` да асобнага радка `:::`.

Сыры HTML не выконваецца і паказваецца як тэкст. Назва малітвы захоўваецца асобна, таму ў пачатку тэксту не патрэбны загаловак `#` з назвай.

Адзінарныя пераносы радкоў захоўваюцца пры паказе. Гэта важна для літаній, дзе просьба і адказ часта знаходзяцца ў суседніх радках аднаго абзаца.

## Рэдактар

Рэжым **Звычайны** адкрываецца па змаўчанні. Ён хавае службовыя знакі Markdown і адразу паказвае загалоўкі, вылучэнне і рубрыкі. Рэжым **Markdown** паказвае нязмененую крыніцу для дакладнай праўкі. Абодва рэжымы рэдагуюць адзін і той жа радок Markdown без прамежкавага HTML або JSON.

Пры ўстаўцы фарматаванага тэксту з Word або сайта рэдактар спачатку чытае HTML з буфера абмену, выдаляе небяспечныя элементы і пераўтварае абзацы, загалоўкі, спісы, тлусты тэкст, курсіў і асобныя рубрыкі ў MyBrev Markdown. Калі ў буферы ёсць толькі просты тэкст, яго пераносы захоўваюцца.

Кнопка **MD autofix** паказвае тэхнічныя прапановы, прычыны і тэкст да/пасля. Змена адбываецца толькі пасля «Ужыць» і можа быць адменена праз Ctrl+Z. Пераўтварэнне HTML і аднаўленне рубрык патрабуюць праверкі зместу; код не выпраўляецца аўтаматычна. Пры адкрыцці рэдактара крыніца не перапісваецца.

Метка ўдзельніка ў пачатку радка (`К.`, `С.`, `Н.`, `Д.`, `Л.`, `Ц.`, `V.`, `R.`) паказваецца тэматычным колерам і тлустым шрыфтам. Кнопкі ўстаўляюць толькі метку. Кантар — `К.`, Святар — `С.`, Народ — `Н.`. Спадчынныя `С.:`/`Н.:` чытаюцца без перазапісу. Курсіў пры ўстаўцы з Word застаецца курсівам; яўная Рубрыка ўстаўляецца асобнай кнопкай.

Дакладная граматыка, выключэнні, мяжа з Імшой і патрабаванні Flutter: [Стандарт фарматавання](prayer-formatting-standard.md). Dry-run аўдыту: `node scripts/autofix-prayer-markdown.mjs`; поўныя прыватныя diff захоўваюцца толькі ў ignored `backups/prayer-formatting/`.

## Спасылкі на іншыя малітвы

Кнопка **Спасылка** адкрывае пошук па назве ў ўжо загружаным спісе малітваў.
Вылучаны тэкст становіцца подпісам; без вылучэння выкарыстоўваецца назва выбранай малітвы.
Подпіс можна змяніць перад устаўкай.

Каб адрэдагаваць існуючую ўнутраную спасылку, пастаўце курсор у яе (або вылучыце яе)
і націсніце **Спасылка**. Дыялог пакажа цяперашнюю малітву і подпіс;
кнопка **Змяніць** заменіць усю спасылку, не закранаючы суседні тэкст.

Унутраная спасылка — звычайная спасылка CommonMark з адносным да кораня шляхам, без дамена:

```md
[Літанія](/prayer/sqIqIfB7tQbom08IPu0t)
```

Ідэнтыфікатар малітвы, а не яе назва, вызначае мэту. Перайменаванне не ламае спасылку.
Flutter-чытач павінен распазнаваць шлях `/prayer/<id>` і адкрываць малітву з гэтым ID.
Для выдаленай малітвы чытач павінен паказаць стан «не знойдзена».

## Схема Firestore

```js
{
  title: '...',
  text: 'Markdown...',
  textFormat: 'mybrev-markdown',
  textFormatVersion: 1,
  tags: []
}
```

Старыя шматмоўныя дакументы могуць мець `titleVersions` і `textVersions`; кожнае значэнне `textVersions` таксама змяшчае MyBrev Markdown. Новы код умее прачытаць стары HTML і пераўтварае яго ў Markdown перад рэдагаваннем. Скрыпт `npm run db:migrate-prayers-markdown` робіць толькі аўдыт; сцяг `-- --apply` запісвае вынік пасля стварэння лакальнай рэзервовай копіі.
