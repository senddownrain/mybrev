# Web-активация S2 и подключение каталога S4

База S1 — `56d398c2c20d505d9476e267bd1b29b1ecf77991` ([PR #320](https://github.com/senddownrain/mybrev/pull/320)).

## Интерфейс сессии

Импорты из `src/services/priestAccessService.js`

| Экспорт | Контракт |
| --- | --- |
| `accessSetsSession` | Реактивный объект только для чтения. `checked` становится true после первой проверки, включая закрытое состояние без подтверждения. |
| `accessSetsSession.mode` | Подтверждённый `legacy`, `canonical`, `suspended` или `null`, если режим неизвестен. Режим и права обновляются одним снимком. |
| `accessSetsSession.active` и `allowedSets` | Есть хотя бы один подтверждённый набор и список наборов. В `legacy` список содержит только `priest` при действующем legacy grant. В `canonical` это объединение legacy `priest` и наборов актуального V2-профиля. В `suspended` список пуст. |
| `accessSetsSession.legacyActive` | Подтверждён доступ к зеркалу в `legacy`. Старые Web-потребители получают это значение через `priestAccess.active`. |
| `accessSetsSession.profileRevision` | Серверная ревизия подтверждённого V2-профиля или `null`. |
| `accessSetsSession.generation` и `revision` | Одинаковый локальный счётчик. Увеличивается при изменении опубликованного снимка и при принудительной очистке, даже если список наборов остался прежним. |
| `startPriestAccess()` | Устанавливает browser lifecycle handlers один раз и инициирует server check. Его возвращаемое `active` сохраняет прежнюю семантику доступа к зеркалу. S4 читает состояние из `accessSetsSession`. |
| `clearPrivateSession()` | Синхронно закрывает опубликованные права и меняет `generation`. Вызывать при потере серверного подтверждения на стороне потребителя. Серверный отзыв запускает отдельный UI action. |

S4 подписывается на `generation` с `flush: 'sync'` и освобождает защищённый кэш, отображаемый текст и результаты поиска. При запуске запроса фиксирует поколение и режим. Перед показом или записью ответа в память сверяет поколение и права повторно. В `legacy` читает зеркало только при `legacyActive`. В `canonical` читает индекс и канонический payload через S1 Lite gateway на `getPriestActivationDb()` из `src/plugins/priestFirebase.js`. Публичная выдача сохраняется во всех режимах.

В текущем Web старые stores и reader очищаются через прежний `priestAccess.revision`. Подключение канонической выдачи, включая reader, deep link, категории, избранное и поиск, входит в S4.

## Совместимость и отзыв

- В S1 отсутствующий документ rollout означает `legacy`. До S1 точный путь rollout отвечает `permission-denied`. В этом случае S2 проверяет серверный legacy grant и открывает только зеркало. После первого подтверждённого ответа S1 ошибка режима закрывает доступ до успешной перепроверки. Остальные ошибки режима всегда закрывают доступ.
- Механизм существующего anonymous Auth `mybrev-priest` сохраняет UID. Proof передаётся только через Lite. Подписки full SDK получают служебные признаки изменения в памяти. Они инвалидируют состояние, а права подтверждаются отдельным чтением с сервера. Проекция временно недоступного V2-профиля перепроверяется раз в минуту в видимой вкладке и при возвращении в приложение.
- Выключение сохраняет UID в `mybrev-access-disable-pending-v4`, читает прежний `mybrev-priest-disable-pending-v3` и повторяет отзыв после reconnect или reload. Незавершённый отзыв закрывает выдачу. Sign-out именованного Auth выполняется после подтверждения обеих веток. Web Locks сериализует активацию и отзыв между вкладками, где браузер предоставляет API. Остальные браузеры сериализуют операции внутри вкладки. Между версиями PWA проверка нужна при интеграции.
- Явное действие пользователя может снять локальный quota breaker. Автоматические проверки не повторяют запросы при исчерпанной квоте.

## Воспроизведение

[Снимок пустой формы на ширине 390 px](s2-web-access.png).

```sh
npm run test:priest
npm run test:access-sets-v2
npm run test:priest:rules
firebase emulators:exec --only auth,firestore --project demo-rules "node scripts/s2-smoke-access.mjs"
npm run build
node scripts/s2-scan-public-build.mjs
```

Smoke блокирует внешние запросы браузера и использует синтетические fixtures. `BENCHMARK_BROWSER_PATH` задаёт путь к Chromium, `S2_SCREENSHOT` — путь для снимка пустой формы. Для прохода со старыми Rules используется отдельная конфигурация Emulator с `firestore.rules` из `c1359b0289db070521e646c844157464802b5073` и `S2_LEGACY_RULES=1`.
