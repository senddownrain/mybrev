# Запуск Web и офлайн-тексты

Исходная сборка — `main` на `1f735ede`. PR #273 добавил девятидневный офлайн-кэш, а PR #306 оставил его доступным только в разработке. Открытые #149 (диагностика первого клика), #305 (комментарии дней) и #331 (Адвент) были проверены отдельно. Их изменения в этот PR не переносились.

До исправлений три запроса HEAD к `malitounik.by` показали, что `/` и `/readings` кэшировались на час, а отсутствующий JS-чанк получал тот же HTML со статусом 200, MIME `application/javascript` и годовым `immutable`.

## Поведение после изменений

- Hosting требует перепроверки HTML на прямых маршрутах. Отсутствующие ресурсы получают 404. Старый кэш ресурсов service worker удаляется при его обновлении, а новые записи проверяются по статусу, MIME и началу JS-ответа. При ошибке загрузки модулей приложение один раз запрашивает свежую оболочку по тому же маршруту. Повторная ошибка оставляет видимую кнопку восстановления.
- Полный сохранённый день или чтение отображаются сразу после восстановления из IndexedDB. Повторная проверка начинается после отрисовки. У публичных запросов есть общий срок ожидания и отмена временных подписок Firestore. Часы при ошибке показывают кнопку повтора. SDK использует многовкладочный режим, а независимый кэш восстанавливает соединение IndexedDB после блокировки.
- Читатель загружает только шаблоны, которые реально запрашивает литургическая сборка, включая зависимости правил полей. Изменение digest в существующем `contentManifest` вызывает чтение только востребованных ресурсов. Прямое чтение востребованного статического текста раз в сутки учитывает редакционные изменения вне манифеста.
- Прогрев заполняет отсутствующие Часы и чтения за вчера, сегодня и семь следующих дней для текущей диацезии. Он запускается после первого показанного текста, когда вкладка видима и пользователь бездействует. Хеш разрешённого дня сохраняет кэш соседних дат при изменении одной записи календаря. Целые записи сохраняются между деплоями. Прогрев пропускает слабую сеть, режим экономии трафика и исчерпанную квоту.

## Как воспроизвести замеры

Запустите локальный Firestore Emulator и задайте `FIRESTORE_EMULATOR_HOST` как `127.0.0.1:<порт>`, а `BENCHMARK_BROWSER_PATH` как путь к Chromium. Вызовите `node scripts/benchmark-web-startup.mjs <worktree-main> <репозиторий-Flutter>`. Скрипт берёт только нужные для литургии публичные данные из зафиксированного бандла и проверяет побайтное совпадение текста между сборками.
