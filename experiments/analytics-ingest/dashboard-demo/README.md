# P08: приватная офлайн-демопанель аналитики (только синтетика)

**SYNTHETIC DATA — НЕТ РЕАЛЬНОЙ СТАТИСТИКИ · ОТКРЫТИЯ ≠ ЛЮДИ.** Это не продукт и не разрешение на сбор: D-01…D-09 открыты, сеть заблокирована. Никакого хостинга, URL, Firestore, Worker/D1, ключей, секретов, production Sentry. Дашборд не публикуется и не вшит в приложение (`src/` его не знает; это проверяет тест).

Цель: через две недели владелец может **увидеть, как будет выглядеть полезная статистика**, не дожидаясь юридического запуска.

## Одна команда

Нужен Node 24 (проверено на 24.2.0; для демо SQLite не нужен, но весь набор `test:analytics-ingest` требует 24).

```bash
npm ci
npm run analytics:dashboard-demo          # пишет experiments/analytics-ingest/dashboard-demo/out/{report.json,report.csv,dashboard.html} (в .gitignore)
open experiments/analytics-ingest/dashboard-demo/out/dashboard.html   # открывается с диска (file://); сеть не нужна
```

Другое место или seed: `npm run analytics:dashboard-demo -- <outDir> --seed 20261024`. Любой другой seed даёт другой отчёт, но тот же формат; «золотые» суммы ниже относятся только к `20261024`.

Если нужен http-просмотр (скриншоты), только loopback: `python3 -m http.server 8765 --bind 127.0.0.1 -d <outDir>` и `http://127.0.0.1:8765/dashboard.html`. Не привязывать к `0.0.0.0`, не пробрасывать наружу.

## Конвейер

```
synthetic.mjs   seed → 21 день (2026-10-17…11-06) × web/android/ios → пакеты контракта v2 (750 публичных ID, 8 функций)
   ↓ каждый пакет → createMockBackend().transport.send → handleIngest (ядро P06, часы внедряются, ~5 % пакетов приходят «на следующее утро»)
   ↓ cleanup(retention 14 дней) удаляет 6 первых дней
rollup.mjs      cell_counts → РОЛЛАП до публикуемой гранулярности → скрытие ячеек n < 5 (suppressSmallCells P06)
   ↓ sanitised report.json (+ report.csv)
build-dashboard.mjs → один html: данные встроены, CSP default-src 'none'; connect-src 'none'; нет CDN, шрифтов, внешних ссылок
scenarios.mjs   14 негативных/граничных сценариев на реальном ядре (тела и ID не показываются)
```

Панель читает **только** встроенный sanitised report. Доступа к `cell_counts`, SQLite, `rows()` у браузерной части нет.

## Что показано

| Блок | Источник (поле отчёта) | Гранулярность до скрытия n<5 |
|---|---|---|
| открытия по дням/платформам, KPI | `screen_view` → `opens` | день × платформа × раздел |
| открытия по разделам | то же | то же (сумма показанных ячеек) |
| каталоги | `catalog_open` → `catalog` | день × платформа × catalog_id |
| время на экране `fv`, `er` («приблизительное время», верхняя оценка), глубина `sd` (`fit,p0_25…p100`) | `text_read` → `text` | платформа × раздел × метрика × корзина (окно) |
| функции (8 из 27) | `feature_use` → `features` | платформа × feature_id (окно) |
| ошибки измерения | `measurement_error` → `errors` | платформа × error_id |
| топ материалов | `screen_view` → `materials` | только prayers/songs/compendium/bible, топ-10, окно, все платформы |
| состояния: приём включён / kill switch / отклонено / нет данных | `states` | реальные ответы ядра |
| сценарии | `scenarios` | HTTP-статус + код |

## Правила приватности отчёта

1. **Сначала агрегация, потом k=5.** Скрытие применяется к публикуемой ячейке, а не к сырой строке; число скрытых ячеек не публикуется; суммы — только по показанным ячейкам и везде «не менее» (lower bound).
2. Фильтры (платформа, раздел) только суммируют показанные ячейки, поэтому сумма при фильтре не раскрывает скрытое вычитанием. Тест возмущений: удаление или изменение любой скрытой ячейки (до k−1) не меняет ни одного байта своего семейства отчёта.
3. Материалы: если скрыт ровно один публичный ID раздела, скрывается ещё один (дополнительное подавление). «Хвост» не суммируется и не показывается.
4. Нет: счётчика людей/устройств/сессий, app_version, region, поиска (только факт `search_open`), точных времён (только дни UTC), даты религиозного материала (`reading:day` — обобщённый), пути по экранам, закрытых материалов и их ID.
5. Это проектное решение, а не юридическая анонимизация.

## Ограничения

- Синтетика не доказывает реальное поведение; распределения — выдуманные (Zipf по материалам, фиксированные веса разделов).
- Сервер **не дедуплицирует** пакеты (в схеме нет id пакета): повтор POST удваивает счётчики; защита только на клиенте (P07: удаление из очереди до отправки, at-most-once). Exactly-once не заявляется.
- Окно хранения 14 дней оставляет 15 календарных дней (граница включена).
- Панель — один файл с отчётом внутри; его нельзя класть на публичный хостинг и нельзя наполнять реальными данными. Реальный read-путь (авторизация, D1) не спроектирован и не реализован: см. `docs/analytics-ingest-release-gates.md`.
- Графики — инлайн SVG без библиотек; проверены в Chromium-панели (desktop, 375 px, light); тёмная тема объявлена через CSS, но здесь скриншотами не проверялась.
